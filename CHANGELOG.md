# Changelog

All notable changes to the `@antadesign/anta` package are documented here.

This file only tracks what ships to npm consumers — anything under `src/`, `dist/`, the build / generator scripts, and root files in the published tarball. Updates to the documentation site at `anta.design` are not consumer-facing and are intentionally not in this changelog; see the commit history for the site narrative.

Versions ending in `-dev.N` are pre-release builds published under the npm `dev` dist-tag; main releases drop the suffix. Always pin a specific version in your `package.json` (`"@antadesign/anta": "0.1.1-dev.1"`) rather than the floating `"dev"` tag — the floating tag tracks the latest dev build and will silently change between installs.

## Unreleased

### Added
- **New `InputDate` component** (`<InputDate>`) — a date field that replaces the native `type="date"` input, **composed** from `Input` + `Menu` + `Calendar` (no `a-inputdate` element; the wrapper is the coordinator, like `Select`). The field takes free text and resolves it on commit (blur / Enter) with a lenient, locale-aware parser: it reads the locale's field order (`06/07/2026` is June 7 in en-US, July 6 in de-DE), month names, and run-together digits, then rewrites the entry to the locale's canonical format. An unrecognized entry marks the field `critical` and keeps the text for the user to fix. The trailing calendar button opens a `Calendar` in a menu (a click in the field just types); picking a day fills the field. The value is an ISO `YYYY-MM-DD` string, controlled (`value` + `onValueChange`) or uncontrolled (`defaultValue`), submitted under `name`. Props mirror `Calendar` (`min` / `max` / `locale` / `size` / `disabled`) plus `Input`'s field surface (`label` / `hint` / `status` / `round` / `clearable` / leading `icon`); the placeholder defaults to the locale's format mask. Exports `InputDateProps` / `InputDateChangeAttrs`.
  - **`time`** turns it into a date-time field: the value becomes ISO `YYYY-MM-DDTHH:mm`, the field parses a 24-hour time after a space (`06/15/2026 14:30`, `… 2:30pm`), and the menu grows a time row under the calendar — two size-matched hour/minute inputs (tabular figures) on the left and a Done button on the right. Picking a day keeps the menu open so you can set the time; Done (or outside-click / Escape) closes it.
- **New date-input engine helpers**, exported from `@antadesign/anta` alongside `buildMonth`: `parseDateInput(text, locale, { min, max })` recognizes a date from free-form text (ISO, locale-ordered numbers with any separator, month names, eight run-together digits) or returns `null`; `formatDateInput(date, locale)` renders the canonical numeric display string; `dateFormatPattern(locale)` returns the placeholder mask (`MM/DD/YYYY`, `DD.MM.YYYY`, `YYYY/MM/DD`). All force latin digits so the parse/format round-trip is deterministic. Their date-time siblings back `InputDate time`: `parseTimeInput` (`14:30` / `1430` / `2:30pm` → `PlainTime`), `parseDateTimeInput` (peels a space-separated trailing time, so `de-DE`'s dotted dates aren't mistaken for one), `formatDateTimeInput`, and `dateTimeFormatPattern`. Type `ParseDateOptions`.
- **New `Calendar` component** (`<Calendar>` / `<a-calendar>`) — a single-date **month grid**, **composed from Anta components in light DOM** (no shadow root). It's the foundation of the InputDate family; free-text entry, the popover/menu shell, time, and month/year jump pickers compose on top of this grid. Registered via the `@antadesign/anta/elements` barrel.
  - **Composed, not hidden** — days and the prev/next chevrons are real `<Button>`s, so their colours, hover/focus/active states, and the selected look come from the Button styles for free and theme themselves; a selected day is literally a `tertiary` Button in its `selected` state, and today is a `secondary` Button. The month/year heading is a `<Button>` that opens an Anta `<Menu>` for jumping the view. It adapts to the range: multiple years (spanning `min`…`max`, defaulting to today ±3 years when unbounded) list as submenus of their twelve months; a single reachable year drops the year level and lists months directly; a single reachable month leaves nothing to jump to, so the heading is disabled. The shown year is highlighted with a trailing dot and its shown month carries a check, so you can see where you're jumping from; picking a month leaps the grid there. The renderer (the `Calendar` JSX wrapper, or any consumer) owns the grid markup, the displayed month, and the roving `tabindex`.
  - **`size`** prop (`small` / `medium` / `large`) scales the day cells, chevrons, heading, and weekday type together.
  - **The `<a-calendar>` element is the interaction authority** — it owns the form value *and* dispatches the events: a click or Enter/Space on a day fires `statechange` / `change`; arrow / Home / End / PageUp / PageDown move focus among rendered cells and emit `navigate` (so the renderer flips the month). This means the element works for a **vanilla** consumer too, not only through the wrapper. It still never builds or mutates its own contents (the no-UI-thread-DOM-mutation rule) — the renderer re-renders in response to the events (the `<a-radio-group>` model).
  - **Temporal-based, with an exported engine** — all date math runs on the [Temporal API](https://tc39.es/proposal-temporal/docs/) via `temporal-polyfill` (a new runtime dependency, statically bundled for deterministic cross-browser behaviour). No raw `Date` crosses the API; the value is an ISO `YYYY-MM-DD` string. The pure engine is exported — **`buildMonth`**, **`getWeekdays`**, **`firstDayOfWeek`**, **`clampDate`**, **`isOutOfRange`**, **`parseISODate`** (+ types `CalendarDay` / `CalendarWeekday` / `CalendarMonth` / `BuildMonthOptions`) — so a non-React consumer can populate their own grid and keep only the element's form + event plumbing.
  - **State** — controlled (`value` + `onStateChange`) or uncontrolled (`defaultValue`), the presence of the element's `value` attribute selecting which. A user pick fires a **cancelable `statechange`** *before* applying (`detail: { next, prev, reason: 'user' }`; `event.preventDefault()` vetoes it uncontrolled), then a post-apply **`change`** → **`onChange(e)`** / **`onValueChange(e, { value, name })`**. Form **reset** and bfcache/autofill **restore** come through as `statechange` (`reason: 'reset' | 'restore'`) + `change`.
  - **Form association** — the `<a-calendar>` element submits the selected ISO date via `ElementInternals` (`setFormValue`, `:state(filled)`) under `name`. No host-DOM mutation: it confines itself to off-DOM work (form value, custom states), event dispatch, and imperative focus of cells that already exist.
  - **Locale** — respects the browser locale (`navigator.language`) unless `locale` (BCP-47) is set. First day of week comes from `Intl.Locale#getWeekInfo()` (never hard-coded to Sunday); weekday (two-letter) and month names are localized via `Intl`.
  - **Range** — `min` / `max` (ISO strings) bound the selectable range: out-of-range days render disabled and skip keyboard focus, and the prev/next month arrows stop at the range edge.
  - **Accessibility** — a labelled **group** of day buttons (a flat grid, not a nested `grid`/`row`/`gridcell` tree): the group is named by the month heading (`aria-labelledby`), each day button's `aria-label` is its full date incl. weekday, the selected day carries `aria-pressed` and today `aria-current="date"`, and the decorative weekday headers are `aria-hidden`. A roving `tabindex` keeps a single tab stop, with an `aria-live="polite"` month announcement. Keyboard: arrows move by day/week, <kbd>Home</kbd>/<kbd>End</kbd> to week edges, <kbd>PageUp</kbd>/<kbd>PageDown</kbd> by month (<kbd>Shift</kbd> by year), <kbd>Enter</kbd>/<kbd>Space</kbd> to select.
  - **Styling** — ordinary light-DOM CSS: `--calendar-cell-size` drives the grid track and square day cells; target `a-calendar a-button[data-part="day-cell"]` (and the `.anta-calendar` shell) directly. Colours come from Anta's role tokens + the Button styles, so dark mode is automatic.
- **`Button`: `role` prop** — an ARIA role override (e.g. `role="gridcell"`), forwarded to the underlying element. Existing buttons are unaffected (defaults to the element's own role).
- New **`calendar-days`** icon shape (lucide), available as `<Icon shape="calendar-days" />` and in the `IconShape` union.
- **`getAnchorRect()` anchor protocol for `Menu` & `Tooltip` positioning.** An anchor element can implement `getAnchorRect(): DOMRect` to have `a-menu` / `a-tooltip` position against a sub-region of itself instead of its full border box; anchors without it fall back to `getBoundingClientRect()` (opt-in, back-compatible). **`a-input` implements it** (returns its `.field` box), so a menu (e.g. `Select`) or tooltip anchored to an `Input` lines up with the field itself rather than the whole component — whose box also spans the label and hint. Exposed as `anchorRect(el)` in `@antadesign/anta/anta_helpers`.
- **New `Select` component** (`<Select>`) — a single- or multi-select dropdown **composed** from `Input` + `Menu` (no `a-select` element; the JSX wrapper is the coordinator). A read-only `Input` trigger shows the chosen value(s) with a chevron that flips on open; a `Menu` of options anchors to the field and opens on click. Options are a JSON array of bare strings or `{ value, label, hint, icon, disabled, tone }` (like `RadioGroup`/`Tabs`). **`selection`** sets behaviour: **`"single"`** (default; `value` is a string, menu closes on pick) or **`"multiple"`** (`value` is a `string[]`, checkbox on each row, menu stays open while toggling, the field shows an "N selected" count, opt-in **`selectAll`** row with a mixed box when partial). For single-select, **`indicator`** picks the per-row mark: **`"none"`** (default, tint-only highlight), **`"check"`** (a trailing checkmark on the selected row plus the tint — the canonical Select look), or **`"radio"`** (a leading radio on every row). **`toneSelected`** tones the selected row(s) — the whole row (label, icon, indicator, tint) takes a named tone or a custom CSS color (equivalent to passing `tone` to just the chosen option). Controlled (`value`) or uncontrolled (`defaultValue`); one callback, **`onValueChange(value, attrs)`** where `attrs` is a discriminated union — `{ value, option, selected? }` for a row toggle, or `{ all: true, selected }` for the Select-all row (no `onStateChange` — Select has no discrete element state to veto, so it mirrors `Input`'s model). **`filter`** adds a search field at the top of the menu that narrows the options as you type — `true` uses the built-in matcher (a case-insensitive substring of value / label / hint that is whitespace-flexible — a typed space matches any run of whitespace — and **bolds the matched substring** in the results), or pass a `(option, query) => boolean` function for custom matching; the menu becomes a combobox (see the Menu note below). A `status` also tints the trailing chevron to match the field. Exports `SelectProps` / `SelectCommonProps` / `SelectOption` / `SelectChangeAttrs` (`value` is a `string` in single mode, a `string[]` in `multiple` — discriminated by `selection`). Sections (grouped options) are still to come.
- **`Select` `renderOption` / `renderIndicator` props + `SelectOption` index signature.** **`renderOption(option, state)`** replaces a row's *content* (the `label` / `hint` / `icon` layout) with your own node; **`renderIndicator(state)`** replaces the row's *selection mark*, drawn at the leading edge. Select still supplies the row box, click, and ARIA — the row stays the control (pair `renderIndicator` with `indicator` `'check'` / `'radio'` or `selection="multiple"` for `role` + `aria-checked`). They compose independently — override the content, the mark, both, or neither. `SelectOption` now carries an index signature (`[key: string]: unknown`), so you can attach arbitrary fields to an option (a `ranAt` date, a `status`, …) and read them back off `option` in `renderOption` (those extra fields are typed `unknown` — cast at the boundary). Both renderers receive an **`OptionState`** (new exported type: `value` / `selected` / `disabled`; the combobox "active" cursor is intentionally omitted, being a live element state not known at render). They compose with everything else: `filter` still matches the option's `value` / `label` / `hint` (match-highlighting is skipped with a custom row — its content owns its display). Give a `renderOption` root `flex: 1; min-width: 0` to fill the row.
- **`Input` `type="search"`** — a wrapper-only shorthand for a search field: it defaults a leading search icon and `clearable` (both overridable — pass your own `leading`, or `clearable={false}`) and sets `inputmode="search"`. The native `search` type never reaches the DOM input, so the browser's own clear/search affordances never appear (which is why `search` was previously excluded from `type`); Anta owns that chrome.
- **`MenuSeparator` accepts text — a caption / status row.** Empty, it's the same hairline divider as before. Given content (`<MenuSeparator>No results</MenuSeparator>`), it renders a small muted caption (`--menu-separator-label-size`, 13px, `--text-3`, normal case — distinct from `MenuGroup`'s uppercase heading) instead of a line, and the wrapper flips its role from `separator` to `status` with `aria-live="polite"` so a changing message is announced. This is the styled home for `Select`'s `renderEmpty` "no results" / "loading" messages (its demo now returns `MenuSeparator`s).
- **`Select` `icon` prop** — a leading icon at the left of the field, rendered in the default trigger's `Input` `leading` slot. With a custom `renderTrigger`, it's not placed automatically — it's passed through on the trigger state as `state.icon` (a new `TriggerState` field) so the consumer can hand it to their own element (e.g. a `Button`'s `icon`).
- **`Select` grouped & nested options.** An `options` entry can now be a **`SelectGroup`** (`{ label, options }` — an inline titled section, rendered as a `MenuGroup`) or a **`SelectSubmenu`** (`{ label, icon?, submenu }` — a flyout branch, rendered as a `MenuItem submenu`), mixed with plain options and nested arbitrarily. Discriminated by shape (`options` array → group, `submenu` array → submenu, else option — so those keys are reserved on an option). Selection stays **global**: the Select's `selection` (single / multiple) applies to every leaf; group headings and submenu parents organize but aren't selectable, and one flat `value` / `onValueChange` / count is unchanged. `disabled` on a group or submenu **cascades** to all descendants. With `filter`, a typed query **flattens** the tree — submenus collapse into inline groups (their `label` becomes the heading) and empty branches drop out, so matches read as one list instead of hiding behind flyouts. New exported types `SelectGroup` / `SelectSubmenu` / `SelectItem` (plus the previously-internal `OptionState` / `TriggerState` / `EmptyState` are now exported).
- **`Select` `renderEmpty` prop** — render content in the menu body when the option list is empty after the filter runs: a "no results" line, a loading indicator, or a "create from the query" row. Receives an **`EmptyState`** (new exported type: `query`, the trimmed filter text — non-empty means the filter hid everything, empty means there were no options). There is **no built-in empty message** (previously the menu showed a fixed disabled "No matches" row): when `renderEmpty` is omitted, an empty list renders nothing. Loading is not a Select prop — the consumer owns the fetch, so a `'Loading…'` branch is gated on their own state. Whatever you return renders where the option rows would: a plain node is inert, or return a `MenuItem` (e.g. a `Create "…"` row) to make it focusable and selectable.
- **`Select` `renderTrigger` prop** — render your own trigger in place of the default field. It receives a **`TriggerState`** (new exported type: `open` / `value` / `selected` / `disabled`) to drive the trigger's look, and returns a single focusable element (an Anta `Button`, say). The menu anchors to it and opens it on click; the consumer's element owns its ARIA (`aria-haspopup="menu"` + `aria-expanded={state.open}`), since a root menu never writes to a trigger it doesn't render. `selected` is the resolved `SelectOption[]`, so a multi-select count is `selected.length`. The field props (`label` / `size` / `status` / …) don't apply to a custom trigger.
- **`MenuItem` `indicator` prop** (`React.ReactNode`) — replace the built-in selection-indicator *visual* (the passive `<a-checkbox>` / `<a-radio>` / trailing `check` glyph) with your own node, drawn at the **leading** edge. `selectionIndicator` still drives the semantics (`role` + `aria-checked`) and the row stays the control; only the mark changes. The node is rendered passive (aria-hidden, no pointer events, `flex: none`) so the row owns the click, and it suppresses the built-in leading mark and the trailing `check`. This is what `Select`'s `renderIndicator` renders.
- **`Menu` fixed header / footer slots + scrolling body.** The menu surface now renders a fixed **`header`** slot and **`footer`** slot around a scrolling body (the default slot, holding the items), exposed as `::part(scroll)`. Content slotted into `header` / `footer` (e.g. a filter field, a footer action) stays pinned while only the items scroll — the scrollbar spans just the option list, not the whole menu. A plain menu leaves both slots empty, so the body fills the surface exactly as before. The body's edges soft-fade on whichever side still has more to scroll; the top additionally clears a hard few-pixel band before the fade, so a row scrolling up vanishes cleanly under a pinned header / filter field instead of bleeding against it.
- **`Menu` combobox mode + `MenuItem` active state.** A `Menu` containing a search field marked `data-menu-search` (slotted into `header`) switches to the WAI-ARIA combobox keyboard: opening focuses the field, `↑`/`↓`/`Home`/`End` move an *active* option cursor while focus stays in the field (so you keep typing), `Enter` activates it, and the menu reflects `aria-activedescendant` onto the field. The menu also **re-anchors to the trigger as its filtered height changes** (so an upward-flipped menu stays against the field instead of floating), and arrow-nav focus now uses `preventScroll`. The cursor is carried by a new `MenuItem` **`active`** element property that mirrors to `:state(active)` off-DOM (no attribute churn, same pattern as `a-radio.selected`), so it survives reactive re-renders. This is what powers `Select`'s `filter`; it also works on a hand-authored `Menu`.
- **`MenuItem` `hint` prop** — secondary text under the label (like `RadioGroup`'s option `hint`). Requires `label`; renders as a new light-DOM `<a-menu-item-hint>` stacked with the label in a column (`<a-menu-item-text>`), while the icon / trailing badge / chevron stay centered on the row. Muted (`--menu-item-hint-color`, default `--text-3`) and tracks the row's `tone` via the theme-aware `--text-3-<tone>` tokens; greys out when `disabled`.
- **`columns-3-cog` icon shape** — a table-columns-with-settings glyph (`<Icon shape="columns-3-cog" />` / `<a-icon shape="columns-3-cog">`), from Lucide, for column-visibility / table-configuration controls. Searchable in the icon gallery under *columns / table / settings / configure / fields / visibility*.
- **`blank` icon shape** — a spacer shape (`<Icon shape="blank" />` / `<a-icon shape="blank">`) that renders nothing but occupies a full icon box at the current `size`. For reserving a leading-icon column so labels align when only some rows carry an icon (menus, lists). Distinct from omitting `shape` (which renders no element); a bare `<a-icon>` with no shape paints a solid square, so `blank` is the correct way to get an invisible sized box. Searchable in the icon gallery under *spacer / empty / placeholder / space / none*.
- **`MenuItem` `selected` prop** (`selected` attribute on `<a-menu-item>`) — marks a row as chosen. On a plain row it's a persistent background tint, the same resting fill a pressed row shows (presence-based like `disabled`, the wrapper emits `selected=""`; touches only the background, no layout shift, tint tracks `tone`). On a checkable row (see `selectionIndicator`) it instead drives the indicator + `aria-checked`.
- **`MenuItem` `selectionIndicator` prop** (`'checkbox' | 'radio' | 'check'`) — turns a row into a checkable item, with the row itself as the control (it flips role + carries `aria-checked`, driven by `selected`). `'checkbox'` / `'radio'` render a **leading passive `<a-checkbox>` / `<a-radio>`** (reusing the element visuals — not the interactive wrappers, so no nested role, focus, or form value; the indicator is `aria-hidden` + `pointer-events: none`) and drop the tint (the mark carries state); `'check'` instead keeps the background tint and adds a **trailing check glyph** on the selected row (the canonical single-select look). Pairs with a new **`indeterminate`** prop (checkbox only → `aria-checked="mixed"`) for a partially-selected "Select all" row. The leading indicator renders before `icon`, so a row can show both; omit for a plain row. This is what `Select`'s `selection` / `indicator` modes render.
- **`MenuItem` `tone` now accepts a custom CSS color** (was named tones only) — like `Button`/`Checkbox`/`Input`, a literal color resolves through `--menu-item-tone-source`, keeping its hue + chroma while the lightness is pinned to match the brand text (light + dark ramps). The `checkbox` / `radio` selection indicator **adopts the row's tone** (named or custom), so a toned selectable row gets a matching mark. Named tones are unchanged.
- **`round` attribute across components** — rounds corners fully (`border-radius: 999px`, clamped by the browser to half the shorter side, so it's a pill on a wide element and a circle on a square one, height-aware with no size math). **Polymorphic**, like `tone`: bare `round` = fully round; a **value** (`<Button round={20} />`, or `<a-button round="20px">`) sets a *custom* radius. The value travels the same dual path as a custom `tone` — a typed `attr(round type(<length>), …)` default for hand-authored elements (newer engines) plus a wrapper-set `--{component}-round` inline var for portability. A custom value applies to the **top-level element only**: `Menu` → the container (items stay full pills), `Tabs` → the track well (tab pills + indicator stay full), `Expander` → a fixed radius that overrides the measured pill. Available on **`Button`** (pill / icon-only circle), **`Input`** (rounds the field; the `clearable` × button is rounded to match), **`Progress`** (rounds the track; the fill clips to it), **`Checkbox`** (circular mark), **`Tabs`** (rounds the tabs + the sliding indicator via `--tab-radius`, plus the primary track well) and **`Tab`** (per-tab), **`Menu`** (container softens to a **20px** radius, items go fully round), **`Tooltip`** (20px bubble), and **`Expander`** (corners sized to half the folded header height — a pill when folded, and the *same* corner radius when expanded rather than a bigger stadium; the element measures the header via a `ResizeObserver` and publishes `--_expander-round-radius`, so it tracks custom header content, on every priority). On the elements it's the `round` attribute (`<a-button round>`, `<a-menu round>`, …).
- **`Tabs` `options` prop** — render tabs from a data array instead of `<Tab>` children (mirrors `RadioGroup`'s `options`): `options={[{ value, label, icon, iconTrailing, tone, disabled, round }]}`. `icon` / `iconTrailing` are icon-shape strings. When `options` is set, `<Tab>` children are ignored; `<TabPanel>` children still supply panel bodies (matched by `value`), so the array + panels compose. New exported type `TabOption`.

### Fixed
- **A `Button` with only non-text content no longer collapses below its size height.** A button whose content carried no line-box and wasn't icon-only — an icon + a `Tag` counter, or icon + icon — lost the icon-only `min-height` floor *and* had no label line-height to hold the box, so it shrank to its children + padding (~23px at medium, vs the 28px of an icon-only or text button). Every button now floors at the same-size Input height (24 / 28 / 32 for small / medium / large); text buttons already reached those, so it's a no-op for them. The inline link-style `priority="quaternary"` + `paddingless` button opts out (`min-height: 0`) so it still sits on the text baseline.
- **`Select` no longer closes when you press ArrowDown after opening it with the mouse.** A mouse open leaves focus on the read-only trigger; its open-on-ArrowDown handler then re-fired and toggled the already-open menu shut. It now only opens while closed — once open, ArrowDown falls through to the menu and moves into the option list. (Menu arrow-navigation also gained `preventScroll` on the item focus, matching the initial-focus path, so arrowing to an off-screen item can't trip the scroll-dismiss.)
- **A `Menu` on an anchor that advertises a smaller `getAnchorRect()` no longer self-dismisses on open.** The open-position tracker (which dismisses the menu once the anchor scrolls out of view) shrank its `IntersectionObserver` window to the anchor's *advertised* rect while observing the whole host element. When the host is much taller than that rect — e.g. an `Input` (and so `Select`) with both a `label` and a `hint`, whose advertised rect is just the `.field` — the intersection ratio started below the 0.5 threshold, so the menu closed the instant it opened. The tracker now windows to the observed element's own box (positioning still uses `getAnchorRect`).
- **A `Menu` inside an iframe no longer dismisses itself on open (or after the outer page scrolls).** The open-position tracker's `IntersectionObserver` used `root: null`, which inside an iframe resolves against the top-level viewport, so its iframe-relative `rootMargin` windowed the wrong region and reported the at-rest anchor as out-of-view — closing the menu a frame after it opened, most visibly once the surrounding page was scrolled. The observer now roots on the anchor's own `documentElement`, keeping the measurement iframe-local (a no-op at top level).
- **Menu items inside a `MenuGroup` now keep the 1px inter-item gap** that top-level items already have. The gap lived only on the menu's scroll body, so grouped rows touched — two adjacent tinted rows (a `selected` row and the active combobox cursor, as in a filtered `Select`) merged into one block. `a-menu-group` now lays its rows out with the same 1px gap.

### Changed
- **`Button`: the secondary variant's inset border is fainter** — its `box-shadow` mixes `currentColor` with `transparent 90%` (was `70%`).
- **A read-only `Input` now shows a pointer cursor** (was the text I-beam), since a read-only field is clicked, not typed into — this also makes it read correctly as the `Select` trigger. Disabled fields keep `not-allowed`; editable fields keep the text cursor.
- **A read-only `Input` ellipsizes an overflowing value** (`text-overflow: ellipsis`) instead of clipping it hard, so a long `Select` value reads as `name …`. Scoped to read-only single-line fields (the `Select` trigger, and any read-only display value); editable inputs keep the default clip (the caret needs the scrolled end), and `textarea` wraps.
- **A root `Menu` is now never narrower than its trigger.** The surface's `min-width` floors to the anchor's width (`max(--menu-min-width, anchor width)`), so a menu at least matches the element it drops from; long items can still make it wider, and it never shrinks below the trigger. Automatic — no opt-in. Content-driven menus whose trigger is narrower than their content are unaffected; menus under a wider trigger grow to match it. Submenu / context (coord) menus are unchanged.
- **`Input` forwards `aria-label` to the internal control.** A bare `<a-input aria-label="…">` (no visible `label`) now names the actual textbox, not just the inert host — so a label-less field, like `InputDate`'s time inputs, is announced. A visible `label` still wins as before.
- **`a-calendar`'s `statechange` no longer bubbles.** It matches `a-menu` (also non-bubbling) so the two events can't collide: a `Calendar` inside a `Menu` (as in `InputDate`) no longer has its selection `statechange` mistaken for a menu open/close by an ancestor menu. The wrapper binds the listener on the element directly, so nothing that used `<Calendar onStateChange>` or a direct listener is affected.
- **A `Menu` opened from within another menu's content now nests on top of it instead of replacing it.** A fresh root menu still closes any unrelated open menu, but when the new menu's trigger lives inside an already-open menu (a menu built into another menu's body — e.g. `Calendar`'s year/month jump menu inside `InputDate`'s popover), it stacks above that menu and leaves it open. Selecting a leaf in the nested menu no longer tears down the container.
- **A `Menu` now opens *at* its selected item.** On open it scrolls the first selected row into view (and, opened via keyboard, seats focus on it) instead of always starting at the top — matching a native `<select>` / macOS menu. "Selected" is any row with `selected`, `aria-checked="true"`, or `aria-selected="true"`; a menu with no such row is unchanged (keyboard-open focuses the first item, mouse-open leaves focus on the trigger). So a `Select` with a preselected value — or the `Calendar` year/month jump menu — opens on the current choice. A multi-select lands on the topmost checked row; a row inside a closed submenu isn't a target (it isn't visible). Scrolling touches only the menu's internal scroll container, never the document.
- **`MenuItem` renders `children` before `kbd` and the trailing icon** (previously last). Children now sit after the label but before the shortcut hint / trailing icon / submenu chevron, so a slotted `<Tag>` badge or counter lands at the row's trailing edge *before* the chevron rather than past it (the label's `flex: 1` right-aligns it). A submenu's nested `<Menu>` is a child too, so it's no longer the item's last child; the end-padding trim is now scoped `:not([submenu])` so submenu chevron spacing is unchanged. Functionally transparent for existing menus — the only visible effect is the improved placement of slotted trailing content.
- **`Tag` is now normal (mixed) case by default; uppercase is opt-in via `allcaps`.** Previously tags rendered uppercase by default with `nocaps` to opt out. The default is flipped: text renders as written (so `GitHub` stays `GitHub`), and the new **`allcaps`** prop (`allcaps` attribute on `<a-tag>`) switches on the uppercase treatment — wider 0.08ch tracking and a 1px size step-down per size. **Breaking, no alias:** remove `nocaps` (it's now the default) and add `allcaps` where you want uppercase. Sizes: named `size`s under `allcaps` reproduce the old uppercase sizes exactly (small 10 / medium 11 / large 12px); normal-case defaults are +1px (small 11 / medium 12 / large 13px) — this also corrects a prior quirk where `size="small"` + `nocaps` rendered at 12px (same as medium) instead of 11.
- **Anchor-buttons (`<a role="button">`) now require a `data-anta` marker to be styled.** Anta's button CSS previously targeted `a-button, a[role="button"]`, so it styled *every* anchor with `role="button"` on the page — including ones Anta never rendered (a third-party menu, an embedded editor's toolbar). The anchor selector is now `a[role="button"][data-anta]`: `role="button"` is a generic ARIA role, so the anchor must opt in explicitly. **`<Button href>` adds `data-anta` automatically — component users see no change.** Only hand-authored anchor-buttons are affected: a raw `<a role="button" tone=…>` (or a routing-library `<Link role="button">`) must now also carry `data-anta` to pick up the styling. The `<a-button>` element is unchanged (Anta owns that tag, always styled).

- **`Menu`: opening no longer closes the menu instantly, and dismiss-on-scroll is now anchor-aware.** A raw page-scroll listener used to dismiss the menu, so the page nudge that opening can cause — the browser scrolling the just-focused first item (keyboard) or the just-clicked trigger (mouse) into view, amplified into a burst of events under `scroll-behavior: smooth` — tripped it the moment the menu opened. Dismiss-on-scroll is now driven by an `IntersectionObserver` on the trigger: the menu closes once the trigger has scrolled more than ~half of its own size out of the spot it held at open. Hover-intent is now mouse-only (the open/close listeners gate on `pointerType === 'mouse'`); on touch and pen the submenu opens on tap and stays open until dismissed or a sibling opens.

## 0.2.3 — June 18, 2026

### Added
- **New `Expander` component** (`<Expander>` / `<a-expander>`) — a collapsible disclosure (a header that toggles a content region). Built on a real `<button>` summary + a grid content region (no native `<details>`), so it follows the WAI-ARIA disclosure pattern with full keyboard support; collapsed content is `inert`. Registered via the `@antadesign/anta/elements` barrel.
  - **State** — uncontrolled (`defaultOpen`) or controlled (`open` + `onStateChange`), following the shared `state` contract: a **cancelable `statechange`** event (`detail: { next, prev }`), `state` / `default-state` attributes, and the `:state(open)` hook.
  - **Title** — `title` takes a string or a node; `level` (1–6) applies the `<Title>` type scale to a string title, or pass a `<Title>` for real heading semantics.
  - **Surface** — `priority` (`secondary` default / `primary` / `tertiary`) and `tone` (the named tones or **any literal CSS color**) tint the fill and text, tracking light/dark automatically; a closed header lightens on hover.
  - **Header** — `actions` renders controls (buttons, tags) at the end of the header, outside the toggle (separately focusable; the title ellipsizes first). `disabled` freezes the header. `outdent` (with `tertiary`) sets the title + body flush with surrounding content.
  - **Styling hooks** — `--expander-gutter` (the shared title/body/chevron inset) plus `--expander-text` / `--expander-text-hover` / `--expander-bg` / `--expander-border`; the `::part(summary)` / `::part(actions)` / `::part(content)` parts; and the `:state(open)` custom state.
- **New `Input` component** (`<Input>` / `<a-input>`) — a text field. The real `<input>` / `<textarea>` lives in the element's shadow DOM, so the field is fully self-contained: focus, IME, autofill, and native form participation (via `ElementInternals`) all work, and the control is reachable for styling through `::part(input)`. Registered via the `@antadesign/anta/elements` barrel. This is Anta's first stateful, form-associated element.
  - **Value** — controlled (`value` + `onChange`/`onInput`) or uncontrolled (`defaultValue`); the controlled value is reflected only when it differs, so the caret survives re-renders. Submits with native forms under `name`, with `formResetCallback` / validity wired through `ElementInternals`.
  - **Label, message & status** — `label` and `hint` take strings **or** React nodes (`hint` is the single message channel). `status` (`critical` / `warning` / `success` / `info` / `brand`) tints the border + `hint` from that tone's role tokens (so dark mode is automatic) and prefixes a glyph; only `critical` marks the field invalid (`aria-invalid`, blocks submission, `:state(invalid)`) — the rest are advisory. Each status has a default glyph (critical→`warning-diamond`, warning→`warning-triangle`, success→`circle-check`, info→`info`, brand→`circle-small-solid`) — override with `statusIcon` (any shape) or drop it with `statusIcon={false}`. The element mirrors the label and the message into the shadow control's `aria-label` / `aria-description` (IDREFs can't cross the shadow boundary), so a screen reader announces both.
  - **Multiline** — `multiline` renders a `<textarea>`; with no `rows` it autogrows from one line (CSS `field-sizing` where supported, a built-in JS resize on Firefox / older Safari), capped by `maxRows`; a fixed `rows` count gives a constant-height box.
  - **Slots & clear** — `leading` / `trailing` paste content flush at the field edges; `clearable` adds a built-in clear button — a real, keyboard-focusable `<a-button>` in the `clear` slot that fires a bubbling `clearrequest` trigger (via a-button's `data-custom-event`), which the element turns into a two-hook clear lifecycle, so it works even before the framework hydrates: a **cancelable** `clearclick` first (`onClearClick` — `preventDefault()` to keep the value), then, if not prevented, the clear itself (empties the field, fires `input`/`change`, refocuses) followed by `clearinput` (`onClearInput`). Bind them on a raw `<a-input>` all-lowercase as `onclearclick` / `onclearinput`. Browser-injected affordances are suppressed — no `type="search"` (it's omitted from the type union), and the native search/number/reveal decorations are reset across browsers. An Anta `<Tooltip>` (or other overlay) attaches by being dropped in as a plain child — projected into a default slot rendered under the field (a no-box overlay like a tooltip takes no space; visible content pushes the hint down), anchored to the field the same way tooltips attach to any other element.
  - **Sizes** — `small` (24px) / `medium` (28px, default) / `large` (32px), each exactly the height of the matching `Button` size, with the type scale and icon tracking the size (small 13/16 + 14px icon · medium 15/20 + 16px · large 17/24 + 18px). The border is an inset `box-shadow`, so width/placement changes never reflow.
  - **Events** — `onInput` (per keystroke) and `onChange` (on commit) carry native DOM timing; `onAnyChange(event, attrs)` unifies them (plus clear) with a convenience `attrs` snapshot (`value`/`name`/`empty`/`valid`/`validationMessage`) for one-line state updates. `onFocus`/`onBlur` and any other DOM handler (`onKeyDown`, `onPaste`, …) are forwarded, on both `<Input>` and the raw `<a-input>`. `autocomplete` and `inputmode` are derived from `type`, and overridable with the `autoComplete` / `inputMode` props (for cases `type` can't express — `current-password`, `one-time-code`, …).
  - **Disabled** — the control is disabled, value/label dim to `--text-4`, the hint to `--text-5`, and slotted leading/trailing content to 50% + non-interactive.
  - **Styling hooks** — `--input-*` tokens are color-only (bg, border, border-hover, focus, text, label, placeholder, hint — `status` re-points border + hint to the matching tone's role tokens); every dimension (height/radius/padding/border-width/font) is a fixed internal literal. Plus the `::part(field | input | label | leading | trailing | clear | hint)` parts and the `:state(filled)` / `:state(invalid)` custom states.
  - **Layout** — the label / field / hint are laid out as a **grid** on the host (single column by default — the familiar stacked form), each exposed as a part. Re-template the grid from your own CSS to move them around: label-on-the-left, a shared label column aligned across a whole form (each field opts into the form's tracks with `grid-template-columns: subgrid`, which reaches through the shadow boundary), or wrapping multi-column layouts. No layout prop — the element's defaults are in `@layer anta`, so your rule wins.
- **New icon shapes** — `eye`, `eye-closed`, `text-cursor-input` (lucide), `circle-small-solid` (a filled dot), and `warning-diamond`. `warning-diamond` is the default `critical`-status glyph and `circle-small-solid` the default `brand`-status glyph on `Input`, both swappable via `statusIcon`.
- **New `Menu` component** (`<Menu>` / `<a-menu>`) with `MenuItem`, `MenuSeparator`, and `MenuGroup`. A dropdown / context menu that anchors to any target: place `<Menu>` immediately after the trigger (its previous element sibling) and it opens on click, positions itself with room-aware vertical flipping + viewport clamping, and dismisses on outside-click, <kbd>Esc</kbd>, or scroll. Rows are dedicated **`<a-menu-item>`s** (not buttons) composing a leading `icon`, a `label` (or `children`), a trailing `kbd` hint, and an optional trailing icon; `tone="critical"` styles a destructive action and `disabled` greys one out. **Submenus are first-class** — pass a nested `<Menu submenu>` on a `MenuItem`'s `submenu` prop to get a chevron + flyout that opens to the side (flips near the edge) on click, or on hover with intent timing via `hover`. **Trigger modes:** click (default), right-click via `context`, and open-at-cursor via `coord`. **Close contract:** selecting a `MenuItem` closes the menu, but arbitrary injected content (a slider, an input) never does — opt an item, a `MenuGroup`, or any container out of closing with `data-menu-open`, or let custom content close with `data-menu-close`. Open state follows the shared `state` contract (see `STATEFUL-COMPONENTS.md`): uncontrolled by default — observe it with the `onStateChange` prop (or the raw cancelable `statechange` event), or call `.open()` / `.close()` / `.toggle()` on the element — or control it via the `open` prop (the `state` attribute, `'open'` / `'closed'`), applying `detail.next` from `onStateChange`. Uncontrolled, `event.preventDefault()` in the handler vetoes a transition. Submenu parent items carry `aria-haspopup="menu"` with live `aria-expanded` reflection; click-trigger anchors get the same `aria-expanded` reflection. Full keyboard support (↑/↓, Home/End, type-ahead, →/← to enter/leave submenus, <kbd>Enter</kbd>/<kbd>Space</kbd> to activate, <kbd>Esc</kbd> to close, <kbd>Tab</kbd> cycles within the open menu). Renders in the top layer via the Popover API (no z-index management); positioning is JS-based and realm-aware (works inside an iframe). Exposes `--menu-bg`, `--menu-border`, `--menu-radius`, `--menu-shadow`, `--menu-padding`, `--menu-min-width`, `--menu-backdrop-filter` and item-level `--menu-item-*` tokens. Registered via the `@antadesign/anta/elements` barrel or granularly (`@antadesign/anta/elements/a-menu`).
- New `square-menu` icon shape (lucide), available as `<Icon shape="square-menu" />` / `<a-icon shape="square-menu">` and in the `IconShape` union.
- **`Tag` gains a `priority` axis** (`secondary` default / `primary` / `tertiary`), matching the Figma `component/tag/*` set and mirroring `Button` / `Expander`. `secondary` is the existing alpha-tint fill; `primary` is a solid fill with white text; `tertiary` is a transparent outline (a deeper-hue border, no fill). It composes with every tone — named or custom — and tracks dark mode. Each tone now declares three hue anchors the priority maps to: **`--tag-tint`** (secondary fill + secondary/primary border), **`--tag-fill`** (the solid primary fill), and **`--tag-edge`** (the tertiary outline, `= --text-2-{tone}`). Custom tones derive all three with pinned oklch lightness/chroma so any input reads as a sibling of the named tones (same approach as `<a-button>`).

### Changed
- **New global `--focus-ring` token; the focus-ring color is unified (and brightened in light mode).** The focus color was duplicated as per-component literals (`--button-focus` / `--input-focus` / `--menu-item-focus` / `--checkbox-focus`, all `#503cb4` light · `#a897fc` dark). It's now a single themed global token — **`--focus-ring`** (light `oklch(0.55 0.2 284.15)`, a touch brighter than the old `#503cb4`; dark unchanged) — that each component's `--{component}-focus` points at. Retune the ring everywhere by setting `--focus-ring`, or a single control by its `--{component}-focus`.
- **`Button` typography and icons now scale with `size`.** `small` / `medium` / `large` move from a fixed 15px font to the **13/16 · 15/20 · 17/24** type scale (matching `Text` and the same-size `Input`), and a leading/trailing icon now tracks the size (**14 / 16 / 18px**). Heights are unchanged (24 / 28 / 32px). Override per instance by styling `<a-button-label>`'s `font-size`/`line-height`, or pass an explicit `<Icon size>`.
- **`Text` / `<a-text>` now sets `text-wrap: pretty`**, evening out widows/orphans on multi-line body copy (headings already use `text-wrap: balance`, and the raw `<p>` reset already used `pretty`). Only affects the non-truncated case — `truncate` clamps in shadow DOM.
- **Tag tones are re-colored to the Figma "secondary" spec — translucent now, not solid.** Each tone's fill and hairline border are now alpha tints of a per-tone hue rather than an opaque `--bg-4-{tone}` surface: in light mode the fill sits at ~10% (neutral ~7%) and the border at ~15% of the hue; dark mode deepens them to ~20% / ~25%. Tone **text** now uses `--text-3-{tone}` (the 80%-alpha tone text) instead of `--text-2-{tone}`. Neutral's tint is a plum-gray that flips light↔dark so it reads as a tint on either surface. A new **`--tag-tint`** token holds that hue — set it alone to re-tint a tag's fill + border together. Consequently `--tag-bg` now defaults to a tint of `--tag-tint` (was a solid `--bg-4`) and `--tag-border` derives from `--tag-tint` at ~15–25% (was `--tag-text` at 9%). Custom tones (`tone="#ff1493"`, etc.) follow the same recipe — fill/border tint the source color, text deepens it to a readable foreground at 80% alpha. `--tag-text` / `--tag-bg` / `--tag-border` / `--tag-separator` are still overridable.
- **Tooltip shadow DOM is one level flatter.** The bubble surface is now the `<slot>` itself (styled `display: block`) instead of a `<div>` wrapping a slot, so the shadow tree carries one fewer node. No API change — `::part(bubble)` (which now resolves to the slot), the `--tooltip-*` tokens, and all behaviour are identical. Verified across Chromium, Firefox, and Safari/WebKit.

## 0.2.2 — June 13, 2026

### Breaking
- **`list-detail-view` icon renamed to `list-collapse` (and restyled to lucide `list-collapse`).** The old filled detail-view glyph is gone; `shape="list-collapse"` is the lucide three-lines-with-chevrons glyph. Migration: rename `shape="list-detail-view"` → `shape="list-collapse"`.
- **Tooltip is pinned under the anchor by default; cursor-following is now opt-in via `follow`.** Previously `<Tooltip>` / `<a-tooltip>` followed the cursor by default. It now pins beneath the anchor (matching the convention used by Material, shadcn, Carbon, Polaris). Pass `follow` for the cursor-tracking behaviour — it trails the pointer and fades by the cursor's distance from the anchor (full within ~10px, transparent by ~100px, snapping away instantly past that), instead of hanging at full opacity and trailing until the close timer fires. **The `static` attribute / prop is removed** — pinning is the default now, so drop it; add `follow` to anything that relied on the old following behaviour. `interactive` is always pinned (it ignores `follow`).

### Added
- **`--tooltip-padding`** token (defaults to `4px 8px`).
- **Tooltip `::part(bubble)`** — the bubble surface inside the shadow popover is exposed as a shadow part, so consumers can style it directly (`a-tooltip::part(bubble) { … }`) for things the `--tooltip-*` tokens don't cover.

### Changed
- **`copy` icon is rotated a quarter-turn.** `<Icon shape="copy" />` / `<a-icon shape="copy">` now ships rotated 90° by default (the orientation used in most places), so consumers no longer need a per-use `transform: rotate(90deg)`.
- **`filter` icon restyled to lucide `list-filter`.** `shape="filter"` is now the three-line stroked `list-filter` glyph (replacing the old filled three-bar shape). Same shape name — no API change.
- **Quaternary buttons are full-weight and full-opacity at rest.** `priority="quaternary"` now uses `font-weight: 400` (was `415`), `letter-spacing: 0.06ch` (slightly looser than the `0.05ch` base), and a full-opacity rest foreground — the `90%`-alpha rest fade introduced in 0.2.0 is removed, so the label sits at the tone's full strength like the other priorities.
- **`Button`, `Text`, and `Title` pin Anta's stylistic sets explicitly.** They now declare `font-feature-settings: 'ss02', 'ss05'` themselves (matching the `:root` default — `ss02` is the alternate `l`) rather than relying on inheritance, so a consumer's own `font-feature-settings` on an ancestor can't silently drop them (the property replaces, it doesn't merge). `<a-button>` re-states it inside its shadow for the same reason it re-states the variation axes.

### Fixed
- **Button ignores empty / whitespace-only / `NaN` children instead of wrapping them.** `Button` auto-wraps text and number children in `<a-button-label>`; it now drops children that carry no visible content — `""`, whitespace-only strings, and `NaN` — rather than emitting a blank label (which added padding/structure for no text). `null`, `undefined`, and boolean children render nothing, and element children still pass through unwrapped; a valid `0` still renders.
- **Button icon padding no longer miscounts a `<Tooltip>` child.** A `<Tooltip>` is invisible (`display: contents` host, out-of-flow popover) but was counted by the `:first-child` / `:last-child` / `:only-child` selectors that drive icon padding — so an icon-only button with a tooltip lost its square padding, etc. Those selectors now discount `a-tooltip` in any position.

## 0.2.0 — June 9, 2026

### Added
- **New `Tag` component** (`<Tag>` / `<a-tag>`). A compact uppercase pill for status, labels, and metadata. CSS-only (no JS, no shadow DOM) like `<Title>` — tone, size, and case are plain attributes. Content is composed from `icon` / `iconTrailing` (icon shapes), `label`, and `value` props, the same way `<Button>` works; `value` is the primary text (default color/weight) and `label`, when paired with a value, renders as a bold "key" before it (same color, weight 600, no divider — a lone label is treated as the primary text and keeps the default styling). Passing raw `children` instead gives a segmented tag: each segment after the first gets a hairline divider (a leading icon stays flush). `tone` takes the five named tones (`brand` / `info` / `success` / `warning` / `critical`), defaulting to a neutral gray when omitted, **or any literal CSS color** for a one-off custom tone (hue kept, lightness/chroma pinned to the named-tone curve via `oklch(from …)`, re-tuned for dark mode — same mechanism as `<Button>`). Named tones source `--text-2-{tone}` / `--bg-4-{tone}`, so light/dark track automatically. `size="small" | "medium" | "large"` (16 / 20 / 24px, default `medium`, matching `Button`); `nocaps` opts out of the default uppercase. Height is intrinsic (line-height + padding, no fixed height, so text is never clipped); tabular figures (`tnum`) plus `ss05` alternate numerals are always on so counts / versions / timers don't reflow. Exposes `--tag-text`, `--tag-bg`, `--tag-border`, `--tag-separator`, `--tag-padding-block`, `--tag-padding-inline`, `--tag-gap`, `--tag-icon-size`, `--tag-label-weight` (the border + separator derive from `--tag-text`). Registered via the `@antadesign/anta/elements` barrel.
- New `tag` icon shape (lucide), available as `<Icon shape="tag" />` / `<a-icon shape="tag">` and in the `IconShape` union (synonyms: `label`, `badge`, `chip`).

### Breaking
- **Stickers extracted to a separate package, `@antadesign/stickers`.** All sticker code and artwork moved out of `@antadesign/anta` — and with it, the `lottie-web` dependency. Removed from this package: the `Sticker` / `StickerAnimated` components and their types, the `<a-sticker>` / `<a-sticker-animated>` elements, and the `@antadesign/anta/stickers`, `@antadesign/anta/stickers/*`, and `@antadesign/anta/generate-stickers.mjs` subpath exports. Apps that don't use stickers no longer install `lottie-web` at all. Migration: `npm install @antadesign/stickers` (it depends on `@antadesign/anta` + `lottie-web`) and change imports — `@antadesign/anta/stickers` → `@antadesign/stickers`, `@antadesign/anta/elements` (for sticker tags) → add `@antadesign/stickers/elements`. The component API (`size`, `label`, `paused`) and the generator are unchanged.

### Changed
- **`<Text>`'s default `priority` is now `secondary` (was `primary`).** A plain `<Text>` (and `<Text tone="…">`) now renders one step softer — `--text-2` / `--text-2-{tone}` instead of `--text-1` / `--text-1-{tone}` — so default body text isn't the strongest foreground. `primary` is now the explicit opt-in for `--text-1`; `tertiary`–`quinary` are unchanged. Migration: add `priority="primary"` to any `<Text>` that relied on the old strongest default.
- **Selected buttons gain an inset ring.** `selected` now adds `box-shadow: inset 0 0 0 1px currentColor` — a 1px outline in the current foreground color (up from the prior 0.5px) — on top of the existing pressed/active look. Declared after the priority blocks so it survives their `box-shadow` cancels regardless of priority.
- **Secondary buttons gain a hairline edge.** The default `secondary` priority now carries `box-shadow: 0 0 1px color-mix(in oklch, currentColor, transparent 50%)` — a 1px outline in the current foreground tone at 50% alpha — giving the tinted chip a subtle border. `primary`, `tertiary`, and `quaternary` explicitly cancel it (`box-shadow: none`).
- **Secondary button rest labels darkened slightly (light mode).** The `secondary` rest foreground is now shifted down `0.05` in oklch lightness (`oklch(from var(--button-fg-secondary-rest) calc(l - 0.05) c h)`) so the label reads a touch stronger. Applied dynamically at the `--button-fg` wiring via the `--button-fg-secondary-l-shift` knob, so it covers every tone — named and custom alike. Hover / active are unchanged, and dark mode zeroes the shift (`--button-fg-secondary-l-shift: 0`).
- **Quaternary button labels are slightly heavier.** `priority="quaternary"` sets `font-weight: 415` (vs the `450` shared default) so the faded quaternary text holds up at its lower opacity.
- **Quaternary buttons now read quieter than tertiary.** A `priority="quaternary"` button's rest foreground is the tone at 90% alpha (`color-mix(in oklch, var(--button-fg-quaternary-rest) 90%, transparent)`) — slightly faded — so it's visually distinct from the full-opacity tertiary (previously the two looked identical at rest). Hover / active restore full opacity.

### Fixed
- **An empty `tone` on a button no longer renders it invisible.** A `tone=""` (e.g. when a consumer clears the prop) matched the custom-tone branch by attribute presence, where the empty value resolved to `transparent` and wiped the button's foreground/background. Both the wrapper and the element now treat an empty `tone` as "no tone" → the neutral default: `<Button>` collapses `tone=""` to omitting the attribute, and the element CSS excludes `[tone=""]` from the custom-tone selector (so a hand-authored `<a-button tone="">` renders neutral too). A missing `tone` attribute was already correct.

## 0.1.1-dev.8 — June 5, 2026

### Added
- **New `Tooltip` component** (`<Tooltip>` / `<a-tooltip>`). A small floating bubble placed as a child of the element it describes — it doesn't affect that element's layout and its content can be anything (slotted light DOM). Shows on hover (after `delay`, default 250ms) and keyboard focus (gated on `:focus-visible`, so a click/tap that merely focuses the anchor doesn't surface it); dismisses on mouse leave, blur, <kbd>Esc</kbd>, or when the anchor scrolls away. On touch devices it opens on **press-and-hold** (~500ms) and lingers ~1.5s after the finger lifts so it stays readable — a quick tap never shows it. Follows the cursor by default; pass `static` to pin it under the anchor, or `interactive` to make the bubble hoverable + clickable (pointer events on, stays open while the cursor is over it — for content like links; implies `static`). `placement="top" | "bottom"` (default `bottom`) auto-flips when there's no room. Renders in the top layer via the Popover API; one tooltip shows at a time, with a short close delay so moving between anchors cross-fades cleanly instead of blinking. Exposes `--tooltip-bg`, `--tooltip-shadow`, `--tooltip-border`, `--tooltip-backdrop-filter`, `--tooltip-radius`, `--tooltip-max-width` (shadow-only theming surface) — so a bubble can be made fully transparent and borderless, or given a real border. The bubble gives its slotted content a normalized text baseline (Anta body typography: `--text-3`, `wdth 100`, `0.02ch` letter-spacing, `1.5` line-height) so the anchor's text styling — e.g. a `<Button>`'s condensed width axis or letter-spacing — doesn't bleed into it; customise a single tooltip's text with a class on your content.
- **Granular element registration / smaller bundles.** Each element can now be imported on its own — `import '@antadesign/anta/elements/a-tooltip'` registers just that element **and loads its CSS**, pulling in only that element's code. A tooltip- or button-only app no longer ships `lottie-web` (which only `a-sticker-animated` needs). The convenience barrel is unchanged: `import '@antadesign/anta/elements'` still registers everything. Implementation: each `a-{name}` module self-registers and imports its own CSS on load; the barrel re-exports them.

### Dependencies
- Added [`es-toolkit`](https://es-toolkit.dev) (`1.47.0`) as a runtime dependency. It's imported with named, tree-shakeable imports, so consumer bundlers include only what's used — currently just `debounce` (in the `<a-tooltip>` element).

### Fixed
- **Anchor-buttons (`<Button href>` / `<a role="button">`) no longer pick up link colour + underline** from Anta's global link reset. `a:link` / `a:visited` are pseudo-classes with the same `(0,1,1)` specificity as `a[role="button"]`, so they tied the button rule and won on source order. The reset's link selectors now exclude `[role="button"]` (`a:not([role="button"])…`), so anchor-buttons keep their button styling. Affects `reset.css`.
- **Button & link `:hover` styles no longer stick after a tap on touch devices.** Hover-only appearance changes (button color/background per priority, the tertiary/quaternary underline, and the global `a` / `a-text a` link hover) are now gated behind `@media (hover: hover) and (pointer: fine)`, so they apply only on real-pointer devices. On touch, buttons and links return to their rest state after a tap instead of keeping the hover look until the next tap elsewhere; `:active` / `[selected]` press feedback is unchanged. Affects `a-button.css`, `reset.css`, and `a-text.css`.

## 0.1.1-dev.7 — June 3, 2026

### Added
- **New `Button` component** (`<Button>` / `<a-button>`). Five named tones (`neutral` default / `brand` / `info` / `success` / `warning` / `critical`) plus any literal CSS color as a custom tone; four priorities (`primary` / `secondary` / `tertiary` / `quaternary`); three sizes (`small` / `medium` / `large`); `icon` / `trailingIcon`, `label`, `loading`, `selected`, `disabled`, `paddingless`; anchor mode via `href`. Registered via the `@antadesign/anta/elements` barrel.
- New `rotate-ccw` icon shape (lucide), available as `<Icon shape="rotate-ccw" />` / `<a-icon shape="rotate-ccw">` and in the `IconShape` union.

### Breaking
- **Background tokens renamed to a numeric elevation scale.** The named background custom properties are replaced by `--bg-1 … --bg-5` (by elevation, 1 = deepest / recessed, 5 = most raised): `--bg-section`→`--bg-1`, `--bg-base`→`--bg-2`, `--bg-pane`→`--bg-3`, `--bg-block`→`--bg-4`, `--bg-spot`→`--bg-5`. Tinted variants follow the number: `--bg-base-info`→`--bg-2-info`, `--bg-spot-info`→`--bg-5-info`, etc. `--bg-1` is neutral-only (no tinted variant). Values are unchanged. `--text-1…5` and `--border-1…5` are unaffected. No back-compat aliases are shipped (prerelease). Migration: rename `var(--bg-base)`→`var(--bg-2)` and so on; if you prefer named tokens, alias them in your own `:root` (e.g. `--bg-base: var(--bg-2)`).
- **`<Button>`'s `iconButton` prop is removed** and **`leadingIcon` is renamed to `icon`**. Icon-only behavior is now purely structural: pass `icon` with no `label`, `trailingIcon`, or `children`, and the existing CSS rule (`a-button:has(> a-icon:only-child)`) gives the host the square padding + min-size pin. No opt-in attribute. Migration: `<Button iconButton leadingIcon="check" />` → `<Button icon="check" />`; `<Button leadingIcon="check" label="…" />` → `<Button icon="check" label="…" />`. `trailingIcon` is unchanged.

### Changed
- **Button sizes grew 2px taller.** Vertical padding gained 1px top and bottom across all sizes (and horizontal padding 1px each side to match), so the default `medium` button is now **28px** tall (was 26): `small` 22 → 24, `medium` 26 → 28, `large` 30 → 32. `padding-y` is now 3 / 5 / 7 and text-edge `padding-x` 7 / 9 / 13 (small / medium / large); icon-edge padding stays text-edge − 2px. Icon-only square buttons track the same heights (min-size 24 / 28 / 32). Font size and the 18px label line-box are unchanged.
- **Dark theme palette comprehensively retuned.** Every dark-mode background and border token — neutral plus all five tinted tones (brand / success / critical / warning / info) — was reworked into hand-tuned `hsl()` values, deepened from the Anta 0.2 baseline so dark surfaces and borders read with less glare. The dark background and border ramps are now authored in HSL; light mode and dark text tokens are unchanged.
- **Raw `<code>` now sets `line-height: 1em`** (in `src/reset.css`, `@layer anta`) so inline code no longer inflates the line box of the prose it sits in.
- **Neutral secondary button background retuned.** Light mode evens out its rest→hover→active ramp — active drops from ~20% to ~15% alpha (`#44374b33` → `#44374b26`), giving ~7 → 10 → 15% instead of the abrupt 7 → 10 → 20. Dark mode is retuned to ~11 → 14 → 18% (`#e4d1ef` at `1c`/`24`/`2e`, from `1a`/`26`/`33`). Other tones unchanged.
- **Dark neutral `--bg-base` / `--bg-section` adjusted** (now `--bg-2` / `--bg-1` after the rename above). `--bg-base` lightened to `hsl(280 10% 5.5%)` and `--bg-section` set to near-black `hsl(280 20% 0%)`, so the deepest surface now sits *below* the page base in lightness — elevated / code surfaces read as recessed rather than raised. `--bg-block` and `--bg-spot` (now `--bg-4` / `--bg-5`) were also nudged (`#161316` / `#1a171b`); `--bg-pane` (`--bg-3`) and all tinted tones are unchanged. (These were later converted from `hsl()` to hex.)
- **Dark tinted button fills bumped (secondary, tertiary, custom tones).** The five named tinted tones (`brand` / `critical` / `info` / `success` / `warning`) step their dark-mode **secondary** fill to 23 → 28 → 33% alpha (rest / hover / active), from ~15 → 20 → 25%; their **tertiary** hover/active fills move in lockstep to 23 → 28%. Custom (color-literal) tones get the same dark ramp via the `--_tone-bg-a-*` knobs (`0.23 / 0.28 / 0.33`). Neutral steps its secondary rest up to ~11% (~11 → 14 → 18% secondary, ~8 → 13% tertiary).
- **Loading stripe animation sped up** — `--button-loading-duration` default `1s` → `0.5s` (override per-instance to taste).
- **Link hover no longer repaints the underline color.** `a:hover` now only thickens the underline (0.5px → 1px); the underline keeps its resting hairline color (the `currentColor` 75% mix) instead of switching to the solid `--link-color-hover`.
- **Quaternary button press feedback (light mode).** `priority="quaternary"`'s `:active` now lightens the rest foreground by `0.05` in oklch lightness (`oklch(from var(--button-fg-quaternary-rest) calc(l + 0.05) c h)`) for a subtle pressed look, instead of snapping back to the rest color. Dark mode is unchanged — it still returns to rest, since lightening would brighten the already-light foreground.
- **Button label `font-weight` softened from `500` to `450`.** Applies to every `<Button>` / `<a-button>` label across all priorities and sizes.
- **Boolean button attributes now render as presence, not `="true"`.** `<Button>`'s `selected` / `disabled` / `loading` / `paddingless` props now emit a presence attribute (`disabled=""`) instead of `disabled="true"`, and the element CSS matches them by presence (`a-button[disabled]`, not `[disabled="true"]`). The wrapper API is unchanged (still boolean props); hand-authored elements keep working whether you write `disabled`, `disabled=""`, or the old `disabled="true"` (presence matches all). ARIA mirrors (`aria-pressed`, `aria-disabled`, `aria-busy`) stay string-valued.
- **Custom-tone `primary` fill now normalizes lightness.** Instead of painting the raw color, a custom `tone` on `priority="primary"` keeps the source hue + chroma but pins its lightness near the Brand primary's (via `oklch(from … L c h)`), with hover/active stepping the lightness — so a too-light or too-dark input still lands at a Brand-like fill. Re-tunes between light and dark through the same knobs, like the named tones. Secondary/tertiary/quaternary (hue-only) are unchanged.

### Fixed
- **`<a-icon>` with a raw `size` attribute no longer collapses to 0×0 on browsers without typed `attr()`** (iOS Safari, Firefox). The `a-icon[size]` rule is now guarded by `@supports`, so where typed `attr()` is unsupported the icon falls back to the visible 16px default instead of vanishing. Use the `<Icon size={N}>` JSX wrapper (which sets `--icon-size` inline) for an exact custom size on those browsers.

## 0.1.1-dev.5 — May 25, 2026

### Breaking
- **`<Button>`'s default tone flipped from `brand` to `neutral`.** Buttons rendered without a `tone=` prop now resolve to the neutral token set (gray fill, soft secondary alpha, neutral text on tertiary / quaternary) instead of the saturated brand purple. The CSS selector that owns the default branch moved from `:where(:not([tone]), [tone="brand"])` to `:where(:not([tone]), [tone="neutral"])`, with the inverse on the explicit `[tone="brand"]` block. Migration: add `tone="brand"` explicitly anywhere you relied on the old default; everything else (icons, labels, sizes, priorities) is unchanged.
- **`<Button tone="custom">` removed.** Pass any literal CSS color as the `tone` instead (`tone="#ff1493"`, `tone="oklch(0.6 0.25 30)"`, `tone="rgb(255 20 147)"`, named colors, anything that parses as `<color>`). The JSX wrapper hands the color to the host via `--button-tone-source` on inline style; the CSS resolver extracts the **hue** with `oklch(from var(--button-tone-source) … h)` and runs it through the brand-tone L/C curve so every priority × state slot is populated automatically — hover/active darken on schedule, secondary alpha overlays anchor to the consumer's color, tertiary and quaternary text colors all derive. Power-user `style={{ '--button-fg-color': '#…' }}` overrides still beat the resolver. Migration: drop the `tone="custom"` literal + the trio of `--button-{bg,fg,br}-color` inline declarations and just set `tone` to the source color. Relative-color `oklch(from …)` is the only modern-CSS dependency (Safari ≥16.4, Firefox ≥113, Chrome ≥119).

### Changed
- `Button`'s `tone` prop type widens: the `'custom'` literal is dropped and the union gains `(string & {})` so any color literal is type-safe while autocomplete on the six named tones stays intact. `AButtonAttributes.tone` mirrors the same widening.
- `<Button>` now defaults to `flex-shrink: 0`. When the button sat as a flex item in a tight parent, it used to compress and silently clip its icon / label because the host carries `overflow: hidden`. The new default makes the button hold its natural width and overflow the parent instead — the loud failure mode. Consumers who want the old shrinkable behavior can opt back in with `style={{ flexShrink: 1 }}` per instance. The dedicated `a-menu > a-button` rule simplified accordingly (it used to set `flex-shrink: 0` itself).
- `iconButton` accepts an `IconShape` string in addition to `boolean`. `<Button iconButton="check" />` is now equivalent to `<Button iconButton leadingIcon="check" />`; if both are set, the string form wins.
- Icon-only buttons gain a `min-width` / `min-height` pinned to the natural square (small 20px, default 24px, large 28px) so a tight flex parent can no longer squeeze the host below the 16px icon.
- Base `cursor: pointer` moved from the (deleted) shadow `:host` style into `a-button.css`, so anchor-mode buttons and JS-only consumers (no element CSS loaded yet) both pick it up.
