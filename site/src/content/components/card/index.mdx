# Card

A surface container: a bordered, toned box that groups related content. The
`Card` JSX wrapper renders an `<a-card>`, which lays out an optional full-bleed
`media` region plus a `header` / body / `footer` stack. Pass `href` to turn the
whole card into a link.

A card stylizes only its own surface, never its content's typography. Pass
`header` and body (`children`) as strings and the wrapper wraps them in a
`<Title>` and a `<Text>` that follow the card's `tone` and `size`; pass your own
nodes to take over. It shares the `tone` / `priority` / `size` vocabulary with the
rest of Anta.

## Anatomy

A card is three stacked sections — `header`, body (`children`), `footer` — plus an
optional full-bleed `media` region. Each is optional; omit unused regions. Spacing comes from one `--card-padding`: the outer inset and the body→footer
gap are a full `--card-padding`, and the header sits a half-step closer to its body
(`--card-padding / 2`). A string `header` becomes a `<Title>` and a string body a
`<Text>`; pass your own node (`<Title>`, `<Text>`, a layout) to take over. An
optional `subtitle` renders under the title as smaller text (`<Text size="small">`). There's
no dedicated actions region: lay out header controls (a button, a tag) inside the
`header` itself.

## Priority

`priority` sets the surface. `primary` (the default) is a clean sheet — `bg-1`
in light mode, `bg-4` in dark (and a toned card's cleanest tint: `bg-2-{tone}`
light, `bg-4-{tone}` dark); `secondary` is a subtle fill (`bg-2`, or the deeper
tint for a toned card); `tertiary` is a frosted panel: the `primary` surface
made semi-transparent with a backdrop blur, so it reads over busy, colored, or
image backgrounds (the blur shows where there's detail behind). All three carry
a hairline ring — `border-4` for a neutral card, or the tone's `border-4-{tone}`
when toned (stepping to `border-3` on hover).

## Tone

A semantic `tone` tints the surface, border, and text. The set matches the rest of
Anta: `neutral` (the default) plus `brand`, `info`, `success`, `warning`, and
`critical`. Color comes from the theme tokens, so every tone tracks light and dark
mode. A toned card is how you build a **banner** or **callout** — a filled card
with an icon and a message (add a `footer` for an action):

border, and the `<Title>` / `<Text>` the wrapper adds all derive from the color —
`Title` and `Text` take a custom tone too, so a string `header` / body tints to

## Round

Omit `round` to use the theme's corner radius. Pass a `number` (px) or CSS length
to set a fixed radius; `round={0}` makes the corners square. Bare `round` makes
the card fully round, clamped to its box.

<Preview background="var(--bg-2)" direction="column" gap="8px">
  <Card round={16} header="Custom radius"><Text>A 16px corner radius via <code>round={'{16}'}</code>.</Text></Card>
  <Card round="0" header="Square"><Text>Sharp corners via <code>round="0"</code>.</Text></Card>
</Preview>

```tsx folded
<Card round={16} header="Custom radius">…</Card>
<Card round="0" header="Square">…</Card>
```

There is no dedicated actions region. To place a control in the top-right of the
header, pass a layout node as `header`. For example, use a flex row containing

## Link card

Give a card an `href` and the whole thing becomes a link — a single focusable
anchor, keyboard-activatable, with the `hover` lift and inset focus ring. The
default accessible name uses a text header or body. Custom nodes use their native
content name; pass `aria-label` or `aria-labelledby` to choose a shorter name. A
link card is display content: keep interactive controls (buttons, nested links)
out of it — its text is non-selectable and the whole surface navigates.

## Migrate from shadow parts

The JSX props remain available. Card now emits structural tags instead of flat
slot markup. Raw HTML authors must add those regions explicitly. Replace
`::part(body)` with a selector for `a-card-body`, and make the same replacement
for the other regions. Direct child paths keep an outer Card's overrides from
reaching a nested Card.

Navigation attributes belong on a native `<a data-anta-card-link>` directly
under `a-card`. Its `a-card-layout` child arranges media and content independently
of generic link display rules. JSX creates this structure automatically. Raw
link Cards use:

```html
<a-card>
  <a data-anta-card-link href="/guide">
    <a-card-layout>
      <a-card-content>
        <a-card-body>Read the guide</a-card-body>
      </a-card-content>
    </a-card-layout>
  </a>
</a-card>
```

Changing `href` or `loading` on a raw `a-card` no longer updates a link. The JSX
wrapper renders those updates from props. `aria-*` props and `tabIndex` apply to
the anchor in link mode and to `a-card` otherwise. A text header or body supplies
the default link label; custom content uses its native accessible name unless you
provide `aria-label` or `aria-labelledby`.

`ACardElement` and `register_a_card` are removed. The granular element entry loads
CSS only; bundle usage still pairs JavaScript and CSS for other Anta components.

Reach for the props first: **`tone`** sets the color (any CSS color for a custom
tone — it derives the surface in oklch), **`priority`** the fill, **`size`** the
padding. The one custom-color knob worth keeping is **`--card-tone-source`** (the
color a custom `tone` derives from — set it to drive the palette from your own
variable). The corner radius is **`--card-radius`**.

```

`<h2>`–`<h6>`) as the header; the card zeroes its top margin so it spaces the same

```

Card's layout, focus ring, selected ring, and loading animation use external CSS
and work with `style-src 'self'`. Custom tones and custom radii can produce inline
styles in server-rendered JSX and need separate CSP handling.

Card renders its complete light-DOM structure immediately. Its regions are
`a-card-layout` in link mode, `a-card-media`, `a-card-content`, `a-card-header`,
`a-card-icon`, `a-card-title`, `a-card-body`, and `a-card-footer`. Use child selectors to style
these tags. Card needs no shadow parts or pre-upgrade layout.

Each example keeps its CSS in a `<style>` **inside** its own preview, targeting a
demo class on that preview's card — so the rule you read is literally in the
preview's DOM, next to the element it styles. In your app, swap the demo class for
your own selector.

**Scroll a capped body.** The card never scrolls, and the body doesn't by default.
When you cap the card's height and want the body to scroll instead of the card
growing, that's one line on `a-card-body`:

<Preview background="var(--bg-2)">
  <a-card class="scrollable" style={{ width: '320px', height: '160px' }}>
    <a-card-content>
      <a-card-header>
        <a-card-title>
          <a-title level="5">Release notes</a-title>
        </a-card-title>
      </a-card-header>
      <a-card-body>
        <a-text>Line one. Line two. Line three. Line four. Line five. Line six. Line seven. Line eight. Line nine. Line ten. Line eleven. Line twelve.</a-text>
      </a-card-body>
    </a-card-content>
    <style is:inline>{`
        a-card.scrollable > a-card-content > a-card-body { overflow: auto; }
      `}</style>
  </a-card>
</Preview>

```css folded
/* cap the card's height, then let the body scroll */
a-card.scrollable { height: 160px; }
a-card.scrollable > a-card-content > a-card-body { overflow: auto; }
```
