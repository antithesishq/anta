# Time input

**`InputTime`** is a segmented wall-clock field: one boxed input, like the others,
holding separate **hour** and **minute** sections — plus an **AM/PM** section in
12-hour locales — that behave as a single control. Each section is a native text
input:
<kbd>↑</kbd>/<kbd>↓</kbd> steps its value (wrapping 59 → 00), <kbd>←</kbd>/<kbd>→</kbd>
moves between sections at the caret boundary, and typing a digit fills the section
and advances to the next once it can't hold more. AM/PM accepts its locale text or
`a` / `p`.

A leading clock icon marks the affordance (change it with `icon`). Unlike a text
`Input` (which fills its container), the field **sizes to its content** — a time
is a small, fixed control — so set a `width` (e.g. `style={{ width: '100%' }}`) if
you want it to fill. The value is a 24-hour `"HH:mm"` string (`''` until both hour
and minute are set), never a `Date`. It works controlled (`value` + `onValueChange`)
or uncontrolled (`defaultValue`), and submits under `name` via the native form APIs.

## The field

Focus a section and edit it with the keyboard: <kbd>↑</kbd>/<kbd>↓</kbd> to step (it
wraps), <kbd>PageUp</kbd>/<kbd>PageDown</kbd> for a larger jump on minutes,
or enter the digits. <kbd>Home</kbd>/<kbd>End</kbd>, selection, deletion, and
paste behave as they do in a native text input. Typing
`9` then `3` `0` lands `09:30` and moves across the sections on its own; an
out-of-range digit (a `6` in the minutes) commits and advances immediately.
<kbd>Backspace</kbd> on an empty section selects the previous one. The whole thing
reads as one field while preserving native caret behavior. In a
12-hour field, typing a 24-hour hour converts it and flips AM/PM — `18` becomes
`6 PM`, so pasted 24-hour times work.

## Locale

The clock follows the locale: `en-US` shows 12-hour with an AM/PM section, most
others show 24-hour with none. It's derived from `Intl` (the resolved `hourCycle`),
and the section **order**, the **separator**, and the **AM/PM text** all come from
the locale too — Japanese renders the period first (`午後2:05`), Finnish separates
with a dot (`14.05`), and 24-hour locales drop the AM/PM section entirely. Set
`hour12` to force one clock regardless of locale. The AM/PM section reserves
space for the longer locale label, so its width stays the same when the period
changes.

<Preview background="var(--bg-2)" gap="24px" style="flex-wrap: wrap; align-items: flex-start;">

  <InputTime label="German" locale="de-DE" defaultValue="14:05" />
  <InputTime label="Japanese (12h)" locale="ja-JP" hour12 defaultValue="14:05" />
  <InputTime label="Force 24h" hour12={false} defaultValue="14:05" />
</Preview>

```tsx folded
<InputTime label="US English" locale="en-US" defaultValue="14:05" />   {/* 12-hour: 02 : 05 PM */}
<InputTime label="German"     locale="de-DE" defaultValue="14:05" />   {/* 24-hour: 14 : 05 */}

```

## Size, status, and clearing

`size` (`small` / `medium` / `large`) matches the other inputs' scale; `status`
recolors the box and hint (only `critical` marks it invalid); `clearable` adds a
clear button once a value is set — clearing empties every section back to the
placeholder dashes. `disabled` prevents focus and editing. `readOnly` keeps the time selectable and focusable while preventing edits.

`min` and `max` (24-hour `"HH:mm"`) bound the value: a complete time outside the
range is clamped to the nearest bound as you step or leave the field, and flags
`rangeUnderflow` / `rangeOverflow` for form validity in the meantime.

## Controlled values and clearing

Update `value` from `onValueChange` to control the time. An incomplete time reports
an empty string while the native segments retain the text being edited. Call
`preventDefault()` in `onClearClick` to keep a value when clearing is disallowed.

<Preview>
  <InputTimeInteractions client:load />
</Preview>

```tsx folded
const [value, setValue] = useState('09:30')
const [keep, setKeep] = useState(false)

<InputTime label="Meeting" locale="en-US" value={value} clearable
  onValueChange={(_, attrs) => setValue(attrs.value)}
  onClearClick={event => { if (keep) event.preventDefault() }} />
<Checkbox checked={keep} onStateChange={(_, { next }) => setKeep(next === true)}>
  Keep the value when clearing
</Checkbox>
<Tag>{value || 'Incomplete time'}</Tag>
```

<Disclosure title="Web Component">

Use the web component directly when you are not using React or Preact and a native control does not fit.

Slots supply the label, leading content, clear action, trailing content, and hint.
The owned native inputs remain inside the shadow root. The `segments` part groups
them; `hour`, `minute`, and `period` keep their meanings in every locale.

JSX groups slot content in CSS-only `a-input-time-label`, `a-input-time-leading`,
`a-input-time-clear`, `a-input-time-trailing`, and `a-input-time-hint` tags. These
replace the wrapper's spans. Update span-based consumer selectors to the grouping
tags or slot attributes. Raw HTML can keep its existing slot markup.

Defaults load from external CSS, including under `style-src-attr 'none'`.
Custom `tone`, numeric `round`, and application `style` props can still serialize
inline styles that a policy blocks. Before browser SSR hydration, configure
`hydratingEvents: true` as described in [Browser hydration](/install/#browser-hydration).
Client-only and worker renderers forward events immediately by default.

The canonical value remains `HH:mm`, or an empty string for an incomplete time.
`input` bubbles and is composed; `change` bubbles on commit. A clear action first
fires cancelable, bubbling `clearclick`, then `input`, `change`, and `clearinput`
when accepted. Cancel `clearclick` synchronously to retain the value.

A read-only field emits `change` on blur only for an edit made before it became
read-only. Partial digits remain visible, with an empty canonical value until
editing resumes and completes the time. Removing the field while blur settles
still completes a pending commit, including range clamping on an editable field.

### Native HTML time input

For a form that can use the browser's time picker, add `data-anta` to a regular
time input. It gives the field Anta's resting chrome while the browser keeps its
own picker, validation, and keyboard behavior.

`data-anta-size`, `round`, and a custom-color `tone` use the matching Input
field treatments.

<Preview>
  <input data-anta style={{ marginBottom: '8px' }} type="time" name="reminder-at" value="09:00" />
</Preview>

```html folded
<input data-anta type="time" name="reminder-at" value="09:00">
```

## Styling

<Disclosure title="Styling" anchor={false}>

`InputTime` renders an `<a-input-time>` whose field chrome mirrors `<a-input>`.
Route feedback color through `status`; everything else is reachable as plain CSS on
the host or through `::part()`. Unlayered consumer rules override Anta's layered defaults. `segment` targets every editable input. `hour`,
`minute`, and `period` target one segment type regardless of locale order. `literal`
targets the localized separator. The element also exposes `field`, `segments`,
`leading`, `label`, `hint`, `clear`, and `trailing`. Don't override the internal
`--input-time-*` values directly; they are defaults, not a styling API.

<Preview background="var(--bg-2)">
  <InputTime className="my-time" label="Full width, red" defaultValue="09:30" />
  <style is:inline>{`
    .my-time { width: 100%; }
    .my-time::part(segments) { color: #e5484d; }
    .my-time::part(period) { color: var(--text-3); }
    .my-time::part(literal) { color: var(--text-4); }
  `}</style>
</Preview>

```css folded
/* Make one field fill its container (the default is content-width). Style all
   editable segments, then keep AM/PM and the locale separator quieter. */
.my-time { width: 100%; }
.my-time::part(segments) { color: #e5484d; }
.my-time::part(period) { color: var(--text-3); }
.my-time::part(literal) { color: var(--text-4); }
```

The example classes are consumer selectors; replace them with your own.

Drop the clock icon with the `icon={false}` prop, and point the `segments` part at
a monospaced family for fixed-width digits — a small `padding-top` re-centers the
tighter `1em` line:

      font-family: var(--monospace, ui-monospace, monospace);
      line-height: 1em;
      padding-top: 2px;
    }
  `}</style>
</Preview>

tints the resting + hover border — the focus ring stays the global ring. It's a
color, not a named tone; the named feedback tones live on `status`.
