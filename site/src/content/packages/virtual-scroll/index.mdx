# Virtual scroll

`VirtualScroll` shows lists of any length by mounting only the rows near the
viewport. Scrolling, row measurement, and the scrollbars stay on the browser
thread, so the rows can render in a worker and scrolling never waits for them.
Render [typed rows](#typed-rows), scroll [sideways](#horizontal-scrolling),
[follow a growing list](#growing-list), [mark rows on the
scrollbar](#scrollbar-marks), and [restore a position](#restoring-a-position).
The package is experimental.

## Basic usage

Pass the rows as `items` and render each one with `renderItem`. This list has
1,000 rows of mixed height and mounts about 30 at a time. Scroll, drag the
thumb, or click the track; the **Mounted** tag shows the rows in the DOM.

<VirtualScrollDemo example="large" minHeight={360} />

```tsx
import { VirtualScroll } from '@antadesign/virtual-scroll/bundle'

type LogLine = { id: number, text: string }

export function Log({ lines }: { lines: LogLine[] }) {
  return (
    <VirtualScroll
      items={lines}
      height={300}
      renderItem={line => <><b>{line.id}</b> {line.text}</>}
    />
  )
}
```

Rows are measured as they mount. A row that turns out taller than estimated
pushes the rows above it up and leaves the row at the top edge where it is, so
scrolling up through unmeasured rows does not jump.

<Disclosure title="Install and configure">

`@antadesign/virtual-scroll` is a separate package that builds on Anta. Install
it alongside its peers, Anta `^0.3.30` and React `^19.0.0`:

```sh
npm install @antadesign/virtual-scroll @antadesign/anta react
```

### Full bundle

Use the full bundle as the default setup. One import registers
`<a-virtual-scroll>`, loads its stylesheet, and exports the `VirtualScroll`
component, the typed helpers, and the types:

```ts
import { VirtualScroll } from '@antadesign/virtual-scroll/bundle'
```

### Granular entries (advanced)

Use these only to keep the element out of a server or worker build, or to load
the stylesheet yourself.

| Entry | Contents |
| --- | --- |

| `@antadesign/virtual-scroll/source` | The typed helpers and types alone, with no renderer or DOM, for worker-side renderers. |

With the root entry, register the element once in the browser:

```ts
import '@antadesign/virtual-scroll/elements/a-virtual-scroll'
import { VirtualScroll } from '@antadesign/virtual-scroll'
```

## Horizontal scrolling

Set `contentWidth` wider than the list to scroll sideways: with a trackpad
swipe, Shift + wheel, the horizontal scrollbar, or the Left and Right arrows.
This list has 10,000 rows.

<VirtualScrollDemo example="wide" minHeight={360} />

```tsx folded title="10,000 wide rows"
import { VirtualScroll } from '@antadesign/virtual-scroll/bundle'

export function WideLog({ rows }: { rows: string[] }) {
  return (
    <VirtualScroll
      count={rows.length}
      height={300}
      contentWidth={2400}
      renderItem={index => <div style={{ whiteSpace: 'pre' }}><b>{index}</b> {rows[index]}</div>}
    />
  )
}
```

The list has no height limit. Its position is a row index plus a pixel offset,
and the vertical scrollbar maps to row indices, so it never needs a total pixel
height. Every row is one width: `contentWidth` when it is set and wider than the
list, otherwise the list's. The list never sizes rows from their content, so the
horizontal scrollbar keeps its size and position while scrolling vertically.

Without `contentWidth` there is no horizontal scrolling: rows wrap at the list's
width, long words break, and content that cannot wrap, such as
`white-space: pre`, is clipped. Set `contentWidth` when rows need more room, for
example to a table's column total.

## Growing list

A row arrives every 200ms. With `follow`, the list starts on its last row and
keeps the newest row on the bottom edge.

- Scroll up: the list stops following and the view holds still while rows keep
  arriving. **Following** turns to `no`.
- Scroll back down to the bottom with the wheel, the scrollbar, or End: the list
  follows again on its own.

<VirtualScrollDemo example="growing" minHeight={320} />

```tsx folded title="Follow a growing list"
import { useState } from 'react'
import { Tag } from '@antadesign/anta/bundle'
import { VirtualScroll } from '@antadesign/virtual-scroll/bundle'

export function LiveLog({ rows }: { rows: string[] }) {
  const [following, setFollowing] = useState(true)
  return (
    <>
      <Tag label="Following" value={following ? 'yes' : 'no'} />
      <VirtualScroll
        count={rows.length}
        height={260}
        follow
        renderItem={index => rows[index]}
        onPositionChange={(_, position) => setFollowing(position.stickToBottom)}
      />
    </>
  )
}
```

While following, the mounted rows are aligned to the bottom edge, so a new row
that has not been rendered yet never opens a gap under the last one.

## Scrollbar marks

`marks` draws row indices on the vertical track, and `secondaryMarks` draws a
second set in a muted color under them, for rows the application flags for
another reason, such as bookmarks. A row in both sets shows the `marks` color.
`reveal` brings a row to the middle of the viewport.

The list does not search, bookmark, or style row content. In this demo the
application finds matching rows and passes them to `marks`, keeps its own
bookmarks and passes them to `secondaryMarks`, and draws the highlighted words
and bookmarked rows with its own elements and CSS. Click a row to bookmark it.

<VirtualScrollDemo example="marks" minHeight={360} />

```tsx folded title="Marks from the application's search"
import { VirtualScroll } from '@antadesign/virtual-scroll/bundle'

// The application's own highlighter; the list never touches row content.
function highlight(text: string, query: string, active: boolean) {
  const at = query ? text.indexOf(query) : -1
  if (at === -1) return text
  return <>{text.slice(0, at)}<mark data-active={active ? '' : undefined}>{query}</mark>{text.slice(at + query.length)}</>
}

export function SearchableLog({ rows, query, active, bookmarks }: {
  rows: string[], query: string, active?: number, bookmarks: Set<number>,
}) {
  // The application's search: which rows match.
  const matches = rows.flatMap((row, index) => row.includes(query) ? [index] : [])
  return (
    <VirtualScroll
      count={rows.length}
      height={300}
      marks={matches}
      secondaryMarks={bookmarks}
      reveal={active === undefined ? undefined : { index: active, key: `match:${active}`, target: 'mark[data-active]' }}
      renderItem={index => highlight(rows[index], query, index === active)}
    />
  )
}
```

A reveal runs once per key. When the reader scrolls away, later renders with the
same key leave the view alone, so a search that keeps updating does not pull the
reader back. Marks that touch merge into one, so a common word draws a solid run
instead of a pile of overlapping marks.

## Restoring a position

`initialPosition` opens the list at a row. The list reads it once, on mount.
`onPositionChange` fires 150ms after scrolling settles; pass its detail back
through `initialPosition` to reopen a list where the reader left it, for
example after moving it into a maximized panel.

To jump to a row in a list that is already open, set `reveal` instead. The row
lands in the middle of the viewport, placed from its measured height.

<VirtualScrollDemo example="restore" minHeight={320} />

```tsx folded title="Jump to a row, or reopen where the reader left off"
import { useState } from 'react'
import { Button } from '@antadesign/anta/bundle'
import { VirtualScroll, type VirtualScrollPosition } from '@antadesign/virtual-scroll/bundle'

export function RestorableLog({ rows }: { rows: string[] }) {
  const [saved, setSaved] = useState<VirtualScrollPosition>()
  const [generation, setGeneration] = useState(0)
  const [jump, setJump] = useState<{ index: number, key: number }>()
  return (
    <>
      {/* A new key repeats the jump to the same row. */}
      <Button label="Jump to row 250" onClick={() => setJump(previous => ({ index: 250, key: (previous?.key ?? 0) + 1 }))} />
      {/* A new list opens where the last one settled. */}
      <Button label="Reopen" onClick={() => { setJump(undefined); setGeneration(g => g + 1) }} />
      <VirtualScroll
        key={generation}
        count={rows.length}
        height={260}
        initialPosition={saved}
        reveal={jump && { index: jump.index, key: `jump:${jump.key}` }}
        renderItem={index => rows[index]}
        onPositionChange={(_, position) => setSaved(position)}
      />
    </>
  )
}
```

## Sizing

| Props | Rows fit | Rows do not fit |
| --- | --- | --- |
| Neither `height` nor `maxHeight` | Height of the rows | 500px |
| `height` | `height`, or the rows if taller | `height` |
| `maxHeight` | Height of the rows | `maxHeight` |
| Both | Rows, at least `height`, at most `maxHeight` | `height`, at most `maxHeight` |

The vertical scrollbar appears only while the rows are taller than the list.
Without it, the rows and the horizontal scrollbar take its column.

CSS can also size the list, for example `height: 100%` in a flex layout. When
the measured height differs from the height the list asked for, the list uses
the measured height. An empty list shows `empty` at the minimum row height.

<VirtualScrollDemo example="sizes" minHeight={300} />

```tsx folded title="Short, long, and empty lists"
import { VirtualScroll } from '@antadesign/virtual-scroll/bundle'

const renderRow = (index: number) => `Row ${index}`

export function Sizes() {
  return (
    <>
      <VirtualScroll count={3} renderItem={renderRow} />
      <VirtualScroll count={3} height={160} renderItem={renderRow} />
      <VirtualScroll count={40} maxHeight={160} renderItem={renderRow} />
      <VirtualScroll count={0} empty="No data to display" renderItem={renderRow} />
    </>
  )
}
```

## Input

The list takes a short, fixed set of inputs and only when they would move it.
Every other key press and wheel gesture keeps its browser default and reaches the
page's listeners. That includes text selection, browser back and forward, tab
switching, find, and zoom.

| Input | Action |
| --- | --- |
| Wheel or trackpad, no modifier | Scroll. Outside macOS, pixel wheels move a third of their delta. A notched mouse wheel glides over about 100ms; trackpads, macOS, and reduced motion move at once. |
| Shift + wheel | Scroll sideways. |
| Touch drag | Scroll, with inertia after release. |
| Up, Down | Scroll 60px. |
| Ctrl + Up, Ctrl + Down | Scroll one row. |
| Page Up, Page Down | Scroll 90% of the list's height. |
| Home, End | Go to the first row, or to the end of the last row. |
| Left, Right | Scroll 60px sideways, when `contentWidth` is wider than the list. |
| Click the track | Jump there. Keep dragging to move from the new position. |
| Shift + click the track | Page toward the pointer every 200ms until the thumb reaches it. |
| Drag the thumb | Up to `maxNonVirtualItems` rows, the thumb follows the pointer; beyond that, it maps to row indices. |

Everything else passes through:

- **Other modifiers.** Shift with an arrow, Alt or Meta with anything, and Ctrl
  with anything but Up or Down. Ctrl + wheel is browser zoom and trackpad pinch.
- **Edges.** A key that would not move the list, such as Up on the first row,
  Home at the start, or Left when nothing is hidden on the left.
- **Controls inside rows.** Keys typed into inputs, buttons, links, and editable
  content.
- **Keys a row claims.** A key pressed inside a row reaches the row's own
  listeners first. When one of them calls `preventDefault()`, the list does not
  scroll, as in a native scroller. A table can use this to move a selection with
  the arrow keys.

For shortcuts the application owns, list them in `interceptKeys`, for example
`Mod+f` to open the application's own search instead of the browser's find bar.
`Mod` is Cmd on macOS and Ctrl elsewhere. The list prevents only the browser
default for those combinations; the event still reaches the application's
listeners, and the list does not scroll.

The log under this demo shows who handled each key or wheel gesture. Click the
list, then try Down, Ctrl+F, Alt+Left, Shift+Down, Ctrl+PageDown, and Ctrl +
wheel.

<VirtualScrollDemo example="inputs" minHeight={460} />

```tsx folded title="An application shortcut with interceptKeys"
import { VirtualScroll } from '@antadesign/virtual-scroll/bundle'

export function SearchableList({ rows, openSearch }: { rows: string[], openSearch: () => void }) {
  return (
    <VirtualScroll
      count={rows.length}
      height={240}
      interceptKeys="Mod+f"
      onKeyDown={(event: KeyboardEvent) => {
        if (event.key === 'f' && (event.ctrlKey || event.metaKey)) openSearch()
      }}
      renderItem={index => rows[index]}
    />
  )
}
```

## Typed rows

`VirtualScroll` infers the row type from `items`, so `renderItem` and
`rowClassName` receive typed rows. `items` takes an array or a
`VirtualScrollRangeSource`: an object with a `length` and a `slice(start, end)`
that returns something with `toArray()`, for rows that are built or fetched on
demand. Only the mounted range is read, in one `slice`, never row by row.

```tsx
import { VirtualScroll, type VirtualScrollRangeSource } from '@antadesign/virtual-scroll/bundle'

type LogLine = { text: string, level: 'info' | 'error' }

const buildLine = (index: number): LogLine =>
  ({ text: `Line ${index}`, level: index % 50 === 0 ? 'error' : 'info' })

// A million rows, built only when they are sliced.
const lines: VirtualScrollRangeSource<LogLine> = {
  length: 1_000_000,
  slice: (start, end) => ({ toArray: () => Array.from({ length: end - start }, (_, i) => buildLine(start + i)) }),
}

export function Log() {
  return (
    <VirtualScroll
      items={lines}
      height={300}
      rowClassName={line => line.level === 'error' ? 'error-row' : undefined}
      renderItem={(line, index) => <><b>{index}</b> {line.text}</>}
    />
  )
}

// Does not compile: LogLine has no `message`.
<VirtualScroll items={lines} renderItem={line => line.message} />
```

When the application looks rows up itself, pass `count` instead, and
`renderItem` receives the index. A list takes `items` or `count`, not both.

```tsx
<VirtualScroll count={rows.length} height={300} renderItem={index => rows[index]} />
```

A renderer in a worker gets the same typing from helpers with no renderer or
DOM; see [Browser element and workers](#browser-element-and-workers).

<Disclosure title="Browser element and workers" level={2}>

`VirtualScroll` renders `<a-virtual-scroll>`. Drive the element directly from
plain JavaScript, or from a renderer that cannot use the JSX wrapper, such as
one running in a worker.

### How rows get mounted

The element and the application talk through attributes and events. Every event
detail is plain data, so the renderer can be a worker that reconciles the DOM
from another thread.

1. The application sets `count`.
2. The element measures itself and fires `rangechange` with `{ start, end }`.
3. The application mounts rows `start` to `end - 1` as direct children, in
   order, each with a `data-index` attribute.
4. The element measures the rows and places them.

Input never leaves the browser thread. A wheel turn starts moving the mounted rows
on the same frame, and the element fires `rangechange` again only when it needs
different rows. Until those arrive, the gap shows faint placeholder lines.

```ts
import '@antadesign/virtual-scroll/elements/a-virtual-scroll'

const lines = Array.from({ length: 10_000 }, (_, i) => `Line ${i}`)

const list = document.createElement('a-virtual-scroll')
list.tabIndex = 0
list.setAttribute('count', String(lines.length))
list.setAttribute('height', '300')
list.addEventListener('rangechange', event => {
  const { start, end } = event.detail
  list.replaceChildren(...lines.slice(start, end).map((line, i) => {
    const row = document.createElement('div')
    row.dataset.index = String(start + i)
    row.textContent = line
    return row
  }))
})
document.body.append(list)
```

### When the range changes

The element tracks its position as a row, the anchor, plus `deltaPixels`: the
distance from the list's top edge to the anchor row's top. `deltaPixels` is
negative once the anchor's top has scrolled above the edge.

The range is always `2 × page + 1` rows, where a page is
`2 × ceil(height / item-min-height)` rows. The anchor sits near the top edge,
so the range is shifted down: it holds a page minus a quarter page above the
anchor, and a page plus a quarter page below it. That leaves about the same
room for late rows in both scroll directions. At either end of the list the
range slides instead of shrinking: it starts at row 0, or ends at the last row.

A wheel turn changes only `deltaPixels`, and the element moves the rows it
already has. Once the anchor's top is more than a viewport above or below the
edge, the element re-seats the anchor:

1. It walks from the anchor toward the content on screen, one row at a time,
   adding up row heights until the total reaches a viewport. Rows shorter than
   `item-min-height` count as `item-min-height`. The walk stops early at the
   first row without a measured height, so an estimate never moves content.
2. The row it reaches becomes the anchor. `deltaPixels` gains the heights of the
   rows walked over when moving down, or loses them when moving up, so nothing
   moves on screen.
3. The element recomputes the range around the new anchor and fires
   `rangechange` only if the range differs from the last one.

A few cases work differently:

- An anchor row taller than the viewport stays the anchor until it has scrolled
  fully past, then the anchor steps one row at a time.
- Scrolling past either end of the list puts row 0 at the top edge, or the last
  row at the bottom edge.
- Jumps set the anchor directly, with no walk.
- Near either end, the range has slid against the end of the list, so a re-seat
  can leave it unchanged and fire nothing.

When the range changes, the application only needs to add the new rows and
remove the old ones. Rows in both ranges can stay mounted, with their measured
heights. `VirtualScroll` keys each row by its index, so its renderer reuses them.

Take 10,000 rows in a list with `height="300"` and the default `item-min-height`
of 22, with every row exactly 22px tall. A page is `2 × ceil(300 / 22)` = 28
rows, so the range is 57 rows: 21 above the anchor, the anchor, and 35 below it.
Scrolling down 15px per wheel tick goes like this, at selected ticks:

| Scrolled | Anchor | `deltaPixels` | Rows on screen | Event | Mounted |
| --- | --- | --- | --- | --- | --- |
| 0px | 0 | 0 | 0 to 13 | `{ 0, 57 }` | 0 to 56 |
| 15px | 0 | −15 | 0 to 14 | none | 0 to 56 |
| 30px | 0 | −30 | 1 to 14 | none | 0 to 56 |
| 45px | 0 | −45 | 2 to 15 | none | 0 to 56 |
| 150px | 0 | −150 | 6 to 20 | none | 0 to 56 |
| 285px | 0 | −285 | 12 to 26 | none | 0 to 56 |
| 300px | 0 | −300 | 13 to 27 | none | 0 to 56 |
| 315px | 0, then 14 | −315, then −7 | 14 to 27 | none | 0 to 56 |
| 330px | 14 | −22 | 15 to 28 | none | 0 to 56 |
| 450px | 14 | −142 | 20 to 34 | none | 0 to 56 |
| 600px | 14 | −292 | 27 to 40 | none | 0 to 56 |
| 615px | 14, then 28 | −307, then +1 | 27 to 41 | `{ 7, 64 }` | 7 to 63 |
| 630px | 28 | −14 | 28 to 42 | none | 7 to 63 |
| 915px | 28 | −299 | 41 to 55 | none | 7 to 63 |
| 930px | 28, then 42 | −314, then −6 | 42 to 55 | `{ 21, 78 }` | 21 to 77 |
| 945px | 42 | −21 | 42 to 56 | none | 21 to 77 |
| 1230px | 42, then 56 | −306, then +2 | 55 to 69 | `{ 35, 92 }` | 35 to 91 |

The anchor re-seats about once per viewport of scrolling: here every 20 or 21
ticks. The first re-seat at 315px fires nothing, because the range is still slid
against row 0. From 615px on, each event drops about 14 rows at the top and asks
for about 14 new rows at the bottom. With rows of mixed height, the walk sums their measured
heights, so each step still covers about a viewport, in fewer rows when they
are tall.

When an event fires, the rows already mounted cover the screen while the new
rows render. With every row at the minimum height, the worst case, about 180px
of mounted rows remain below the screen when scrolling down, and about 150px
above it when scrolling up. Taller rows leave more. A renderer that falls
further behind than that, as on a fast fling, shows placeholder lines until
it catches up.

The range also changes when:

- The anchor jumps far away: dragging the thumb, clicking the track, Home or End,
  `reveal`, and `initialPosition`. The whole range changes in one event, and
  placeholder lines show until the new rows arrive. For a click on the track or
  a thumb drag, the list first keeps the old rows on screen for up to 150ms, so
  rows that render in a worker replace them in one step. The thumb moves at once.
- `count` changes near the end of the list, since the range ends at the last
  row. With `follow`, the anchor is the last row, so every appended row fires
  an event.
- The height changes, since a page depends on it.

### How many rows get mounted

A list with up to `max-non-virtual` rows (500 by default) mounts every row, and
its range changes only with `count`. A longer list always mounts:

```text
4 × ceil(height / item-min-height) + 1
```

That's two pages plus the anchor, at every scroll position, including both ends
of the list. With the default `item-min-height` of 22:

| `height` | Page | Rows mounted |
| --- | --- | --- |
| 100 | 10 | 21 |
| 300 | 28 | 57 |
| 600 | 56 | 113 |
| 1000 | 92 | 185 |

The count depends only on `height` and `item-min-height`, not on how tall the rows
are. Taller rows cover more pixels with the same count. At most about
`ceil(height / item-min-height) + 1` rows are on screen, so the list mounts about
four times what it shows. A two-page window is the minimum: the anchor re-seats
only after the content on screen is a full viewport away from it, so a smaller
window would leave blank rows. Set `item-min-height` close to the real smallest
row: at 11, a 300px list mounts up to 113 rows.

### Worker helpers

`@antadesign/virtual-scroll/source` exports typed helpers that import no
renderer and touch no DOM:

| Helper | Returns |
| --- | --- |
| `mapVirtualScrollRange(source, range, render)` | `render(item, index)` for each row in a `rangechange` range. |
| `readVirtualScrollRange(source, start, end)` | The rows from `start` up to `end`, clamped to the source. |
| `initialVirtualScrollRange(options)` | The rows to mount before the first `rangechange`. |
| `virtualScrollPositionAttribute(position)` | An `initial-position` value. |
| `virtualScrollRevealXAttribute(target)` | A `reveal-x` value. |
| `virtualScrollMarksAttribute(indices)` | A `marks` value, or `undefined` when there are none. |

```ts
import {
  mapVirtualScrollRange, type VirtualScrollRange, type VirtualScrollRangeSource,
} from '@antadesign/virtual-scroll/source'

type LogLine = { text: string }

function rows(lines: VirtualScrollRangeSource<LogLine>, range: VirtualScrollRange) {
  return mapVirtualScrollRange(lines, range, (line, index) =>
    h('div', { key: index, 'data-index': index }, line.text))
}
```

`VirtualScrollItem<S>` names the row type of a source, and the element's
attributes are typed: `initial-position` and `reveal-x` only accept four numbers,
and event handlers receive typed details.

</Disclosure>

### Attributes

Each attribute matches the `VirtualScroll` prop of the same name in camel case,
except `max-non-virtual` (`maxNonVirtualItems`) and the `reveal-*` attributes
(`reveal`).

| Attribute | Value | Default | Description |
| --- | --- | --- | --- |
| `count` | number | `0` | Number of rows. |
| `item-min-height` | number | `22` | Minimum row height in pixels; also the estimate for rows not measured yet. |
| `max-non-virtual` | number | `500` | Up to this many rows, every row stays mounted and the scrollbar uses real heights. Ignored when smaller than a page window. |
| `scrollbar-width` | number | `16` | Vertical scrollbar width and horizontal scrollbar thickness, in pixels. |
| `content-width` | number | | Width every row shares, and the only source of horizontal scrolling. Without it, rows take the list's width and wrap. |
| `height` | number | | Height in pixels. See [Sizing](#sizing). |
| `max-height` | number | | Maximum height in pixels. See [Sizing](#sizing). |
| `follow` | boolean | | Start at the end and keep following new rows until the reader scrolls up. |
| `content-key` | string | | Change when rows move to different indices. See [Props](#props). |
| `initial-position` | `anchor delta x stick` | | Position to open at, read on first connect. `stick` is `1` to keep following. |
| `reveal-index` | number | | Row to bring to the middle of the viewport. |
| `reveal-key` | string | the index | Reveal again when this changes. |
| `reveal-target` | selector | | Element inside the revealed row to center. |
| `reveal-x` | `left width insetStart insetEnd` | | Horizontal span to bring into view, in content pixels, clear of insets on either side. |
| `marks` | indices | | Space-separated row indices to mark on the vertical track. |
| `secondary-marks` | indices | | Row indices to mark in a muted color under `marks`. |
| `item-height-fixed` | boolean | | Every row is exactly `item-min-height` tall, so rows are not measured. Pin the row height with CSS. |
| `intercept-keys` | key combinations | | Space-separated combinations, such as `Mod+f Alt+r`, whose browser default the element prevents for the application. |
| `wheel-activation` | `hover`, `settled`, `focus`, `settled-or-focus` | `hover` | When an unmodified wheel starts scrolling the list. |
| `scrollbar-hint` | boolean | | Show the shortcut hint on the scrollbars. |

### Events

Events do not bubble.

| Event | Detail | When |
| --- | --- | --- |
| `rangechange` | `{ start, end }` | The rows to mount change. `end` is exclusive. |
| `positionchange` | `{ anchorIndex, deltaPixels, scrollX, maxScrollX, stickToBottom, atEnd, firstVisibleIndex }` | 150ms after the position last changed. |
| `contentsizechange` | `{ height, width }` | The measured content size changes. `height` is `null` until every row is measured. |

### Slots

| Slot | Content |
| --- | --- |
| Default | Rows, each a direct child with `data-index`. |
| `header` | Content above the rows that scrolls sideways with them. |
| `empty` | Shown when `count` is `0`. |

### CSS states

| State | Meaning |
| --- | --- |
| `:state(scrolling)` | Wheel or touch input arrived in the last 150ms. |
| `:state(scrollable-y)` | The vertical scrollbar is shown. |
| `:state(scrollable-x)` | The horizontal scrollbar is shown. |
| `:state(following)` | The list follows its last row. |
| `:state(at-start)` | The first row is at the top edge. |
| `:state(at-end)` | The end of the last row is in view. |
| `:state(hidden-start-x)` | Content is hidden past the left edge. |
| `:state(hidden-end-x)` | Content is hidden past the right edge. |
| `:state(empty)` | `count` is `0`. |

### Parts

`viewport`, `header`, `rows`, `empty`, `scrollbar` (vertical), and `scrollbar-x`
(horizontal).

</Disclosure>

<Disclosure title="Styling" level={2}>

Size the list with `height` and `maxHeight`, or with CSS on the host. Rows are
your own light-DOM elements; style them with plain CSS. `scrollbarWidth` sets
the scrollbar size. The scrollbar is in the shadow root and takes these colors:

- `--virtual-scroll-thumb`, `--virtual-scroll-thumb-hover`, and
  `--virtual-scroll-thumb-active` color the thumb.
- `--virtual-scroll-bar-bg` colors the scrollbar background.
- `--virtual-scroll-mark-bg` colors the marks.
- `--virtual-scroll-secondary-mark-bg` colors the secondary marks.
- `--virtual-scroll-placeholder-line` draws the placeholder lines. Set it to
  `transparent` to hide them.

```css folded
a-virtual-scroll.log {
  --virtual-scroll-mark-bg: var(--text-1-warning);
}
a-virtual-scroll.log:not(:state(scrolling)) > :hover {
  background: color-mix(in oklch, var(--text-1-brand) 5%, transparent);
}
```

Rows and the `header` inherit `--virtual-scroll-x`, the horizontal offset. A
pinned cell can use one rule that also works when the same rows render in a
native scroller, where `position: sticky` does the pinning and the variable is
unset:

```css
.pinned {
  position: sticky;
  left: 0;
  translate: var(--virtual-scroll-x, 0px) 0;
}
```

</Disclosure>
