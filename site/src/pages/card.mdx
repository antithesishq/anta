# Card

A surface container: a bordered, toned box that groups related content. The
`Card` JSX wrapper renders an `<a-card>`, which lays out an optional full-bleed
`media` region plus a `header` / body / `footer` stack. Pass `href` to turn the
whole card into a link.

`header`, body (`children`), and `footer` are respected as you pass them — the
element supplies default typography, so a string reads as a title or body text
with no extra markup. It shares the `tone` / `priority` / `size` vocabulary with
the rest of Anta.

## Anatomy

A card has four content zones, each optional — an empty zone reserves no space.
`header` sits at the top with title typography, the body (`children`) below it
with `<Text>`-style typography, `footer` at the bottom as a left-aligned row, and
`actions` at the top-right of the header row. Pass a string and the element styles
it; pass your own node (`<Title>`, `<Text>`, buttons) to take over.

<Preview background="var(--bg-2)">
  <a-card style={{ width: '360px' }}>
    <span slot="header">Card title</span>
    <Button slot="actions" size="small" priority="tertiary" icon="more" aria-label="More" />
    <span>The body sits under the header with default text styling. Every zone is optional.</span>
    <Button slot="footer" size="small" label="Action" />
  </a-card>
</Preview>

{/* These docs render statically, so previews with a header/actions/footer use the
    equivalent `<a-card>` element composition — a vnode passed as a prop (e.g.
    `header={<…>}`, `footer={<…>}`) is dropped by Astro's static SSR. In your app the
    `<Card>` JSX props in the folded code are the API. String props + children are fine. */}

```tsx folded
<Card
  header="Card title"
  actions={<Button size="small" priority="tertiary" icon="more" aria-label="More" />}
  footer={<Button size="small" label="Action" />}
>
  The body sits under the header with default text styling. Every zone is optional.
</Card>
```

A plain-string `header` is styled as a title (the `Title` level-4 scale) but adds
no heading to the document outline. For real outline semantics, pass a `<Title>`
(or an `<h2>`–`<h6>`) — the card zeroes its top margin so it still sits flush:

<Preview background="var(--bg-2)">
  <a-card style={{ width: '360px' }}>
    <Title slot="header" level={4}>Heading semantics</Title>
    <span>The header is a real <code>{'<Title>'}</code> — in the page outline, with its top margin zeroed so it sits flush.</span>
  </a-card>
</Preview>

```tsx folded
<Card header={<Title level={4}>Heading semantics</Title>}>
  The header is a real heading node, in the page outline.
</Card>
```

## Priority

`priority` sets the surface. `primary` (the default) is a clean sheet — `bg-1`
in light mode, `bg-4` in dark (and `bg-4-{tone}` for a toned card); `secondary`
is a subtle fill (`bg-2`); `tertiary` is a frosted panel: the `primary` surface
made semi-transparent with a backdrop blur, so it reads over busy, colored, or
image backgrounds (the blur shows where there's detail behind). All three carry
a hairline ring — `text-2` at 10% for a neutral card, or the tone's `border-4`
when toned.

<Preview align="stretch" gap="16px" background="repeating-linear-gradient(45deg, color-mix(in srgb, var(--text-5), transparent 90%) 0px, color-mix(in srgb, var(--text-5), transparent 90%) 2px, transparent 2px, transparent 40px), repeating-linear-gradient(135deg, color-mix(in srgb, var(--text-5), transparent 90%) 0px, color-mix(in srgb, var(--text-5), transparent 90%) 2px, transparent 2px, transparent 40px), transparent">
  <Card style={{ flex: '1 1 160px', minWidth: '160px', width: 'auto' }} header="Primary (default)">A clean sheet (<code>--bg-1</code> light, <code>--bg-4</code> dark).</Card>
  <Card style={{ flex: '1 1 160px', minWidth: '160px', width: 'auto' }} priority="secondary" header="Secondary">A subtle fill (<code>--bg-2</code>).</Card>
  <Card style={{ flex: '1 1 160px', minWidth: '160px', width: 'auto' }} priority="tertiary" header="Tertiary">Frosted — the primary surface, semi-transparent, over a backdrop blur.</Card>
</Preview>

```tsx folded
<Card header="Primary (default)">…</Card>              {/* primary is the default */}
<Card priority="secondary" header="Secondary">…</Card>
<Card priority="tertiary" header="Tertiary">…</Card>
```

## Tones

A semantic `tone` tints the surface, border, and text. The set matches the rest of
Anta: `neutral` (the default) plus `brand`, `info`, `success`, `warning`, and
`critical`. Color comes from the theme tokens, so every tone tracks light and dark
mode. A toned card is how you build a **banner** or **callout** — a filled card
with an icon, a message, and an action:

<Preview background="var(--bg-2)" direction="column" gap="8px">
  <a-card tone="info" priority="primary">
    <span slot="header"><Icon shape="info" /> Heads up</span>
    <span>Deploys are paused while the migration runs. They resume automatically when it finishes.</span>
  </a-card>
  <a-card tone="success" priority="primary">
    <span slot="header"><Icon shape="circle-check" /> All checks passed</span>
    <span>Your build is green across every configuration.</span>
  </a-card>
  <a-card tone="warning" priority="primary">
    <span slot="header"><Icon shape="warning-triangle" /> Approaching quota</span>
    <span>You've used 90% of this month's compute.</span>
    <Button slot="footer" size="small" label="Upgrade plan" />
  </a-card>
  <a-card tone="critical" priority="primary">
    <span slot="header"><Icon shape="warning-diamond" /> Deployment failed</span>
    <span>The production rollout was halted after a failing health check.</span>
    <Button slot="footer" size="small" label="View logs" />
  </a-card>
</Preview>

```tsx folded
<Card tone="info" priority="primary" header={<><Icon shape="info" /> Heads up</>}>…</Card>
<Card tone="success" priority="primary" header={…}>…</Card>
<Card tone="warning" priority="primary" header={…} footer={<Button size="small" label="Upgrade plan" />}>…</Card>
<Card tone="critical" priority="primary" header={…} footer={<Button size="small" label="View logs" />}>…</Card>
```

`tone` also accepts **any literal CSS color** for a one-off tint — the hue is kept
while lightness and chroma are pinned to the named-tone curve (and re-tuned for
dark mode), the same mechanism as `Button` / `Expander` / `Tag`:

<Preview background="var(--bg-2)" direction="column" gap="8px">
  <Card tone="#ff1493" priority="primary" header="Magenta">Custom hue, derived surface + text.</Card>
  <Card tone="rebeccapurple" priority="primary" header="Purple">Custom hue, derived surface + text.</Card>
  <Card tone="#0d9488" priority="primary" header="Teal">Custom hue, derived surface + text.</Card>
</Preview>

```tsx folded
<Card tone="#ff1493" priority="primary" header="Magenta">…</Card>
<Card tone="rebeccapurple" priority="primary" header="Purple">…</Card>
<Card tone="#0d9488" priority="primary" header="Teal">…</Card>
```

## Round

`round` softens the corners. A `number` (px) or CSS length sets a custom radius —
the usual choice for a card (`round="0"` squares them); bare `round` goes fully
round (`999px`, clamped to the box). Omit it for the default (`--card-radius`, 8px).

<Preview background="var(--bg-2)" direction="column" gap="8px">
  <Card round={16} header="Custom radius">A 16px corner radius via <code>round={'{16}'}</code>.</Card>
  <Card round="0" header="Square">Sharp corners via <code>round="0"</code>.</Card>
</Preview>

```tsx folded
<Card round={16} header="Custom radius">…</Card>
<Card round="0" header="Square">…</Card>
```

## Actions

Pass `actions` to render controls at the top-right of the header row. They sit
outside the header text, so a long title ellipsizes first and the actions keep
their size. This is the same slot `Expander` uses.

<Preview background="var(--bg-2)">
  <a-card style={{ width: '340px' }}>
    <span slot="header">Production database</span>
    <Button slot="actions" size="small" priority="tertiary" icon="more" aria-label="More" />
    <Text>Region us-east-1 · 4 vCPU · 16 GB</Text>
  </a-card>
</Preview>

{/* These docs render statically, so the preview uses the equivalent element
    composition — passing the `actions` vnode as a prop is dropped by Astro's
    static SSR. In your app, the JSX `actions={…}` form below is the API. */}

```tsx folded
<Card
  header="Production database"
  actions={<Button size="small" priority="tertiary" icon="more" aria-label="More" />}
>
  <Text>Region us-east-1 · 4 vCPU · 16 GB</Text>
</Card>
```

## Footer

`footer` is a **left-aligned** row (it wraps under pressure) — the opposite of
`Dialog`'s right-aligned footer, since a card reads as left-aligned content rather
than a decision surface. Pass several buttons as a fragment.

<Preview background="var(--bg-2)">
  <a-card style={{ width: '340px' }}>
    <span slot="header">Invite teammates</span>
    <Text>They'll get access to this project and its test runs.</Text>
    <Button slot="footer" priority="primary" size="small" label="Send invites" />
    <Button slot="footer" size="small" label="Copy link" />
  </a-card>
</Preview>

```tsx folded
<Card
  header="Invite teammates"
  footer={<><Button priority="primary" size="small" label="Send invites" /><Button size="small" label="Copy link" /></>}
>
  <Text>They'll get access to this project and its test runs.</Text>
</Card>
```

## Media

Pass `media` for a full-bleed image or illustration — it escapes the card padding
and clips to the corners. `mediaPosition` places it on the `top` (the default),
`bottom`, `left`, or `right` edge.

```tsx folded

{/* mediaPosition also takes "bottom" and "right" */}
```

## Link card

Give a card an `href` and the whole thing becomes a link — a single focusable
anchor, keyboard-activatable, with the `hover` lift and inset focus ring. The
accessible name comes from the header (falling back to the body, then the URL), so
a screen reader announces one concise link instead of the whole card's text. A
link card is display content: keep interactive controls (buttons, nested links)
out of it — its text is non-selectable and the whole surface navigates.

<Preview background="var(--bg-2)" direction="column" gap="8px">
  <a-card href="https://antithesis.com/docs/using_antithesis/ci/" target="_blank" rel="noopener">
    <span slot="header"><Icon shape="book-open" /> CI integration guide</span>
    <span>Wire Antithesis into your pipeline in a few minutes.</span>
  </a-card>
  <Card href="https://github.com/antithesishq/antithesis-skills" target="_blank" rel="noopener" priority="primary" tone="brand" header="Antithesis skills for agents">
    Use AI to bootstrap your system into Antithesis and write test properties.
  </Card>
</Preview>

```tsx folded
<Card
  href="/docs/ci"
  header={<><Icon shape="book-open" /> CI integration guide</>}
>
  Wire Antithesis into your pipeline in a few minutes.
</Card>
```

Set `target` / `rel` for a new-tab link (`target="_blank" rel="noopener"`), or
`aria-label` to override the derived link name.

## Composing the element directly

Without the JSX wrapper, `slot` is the wire format: put `slot="media"` /
`slot="header"` / `slot="actions"` / `slot="footer"` on your own elements (several
can share `slot="footer"`); anything unslotted becomes the body.

<Preview background="var(--bg-2)">
  <a-card href="#" style={{ width: '340px' }}>
    <span slot="header">Hand-authored markup</span>
    <a-text>Everything without a <code>slot</code> attribute is the body.</a-text>
  </a-card>
</Preview>

```html
<a-card href="/x">
  <img slot="media" src="/hero.jpg" alt="" />
  <span slot="header">Hand-authored markup</span>
  <a-text>Everything without a slot attribute is the body.</a-text>
  <!-- several elements can share slot="footer" -->
  <a-button slot="footer">Save</a-button>
</a-card>
```

<Disclosure title="Styling">

Reach for the props first: **`tone`** sets the color (any CSS color for a custom
tone — it derives the surface in oklch), **`priority`** the fill, **`size`** the
padding. The one custom-color knob worth keeping is **`--card-tone-source`** (the
color a custom `tone` derives from — set it to drive the palette from your own
variable). The corner radius is **`--card-radius`**.

```tsx folded
<Card tone="#e0457b" header="Custom" />
```

For everything else, `<a-card>` exposes shadow **parts** —
`::part(container)` (the box / anchor), `::part(media)`, `::part(content)`,
`::part(header)`, `::part(actions)`, `::part(body)`, `::part(footer)` — which you
style directly.

Each example keeps its CSS in a `<style>` **inside** its own preview, targeting a
demo class on that preview's card — so the rule you read is literally in the
preview's DOM, next to the element it styles. In your app, swap the demo class for
your own selector.

**Scroll a capped body.** The card never scrolls, and the body doesn't by default.
When you cap the card's height and want the body to scroll instead of the card
growing, that's one line on `::part(body)`:

<Preview background="var(--bg-2)">
  <a-card class="scrollable" style={{ width: '320px', height: '160px' }}>
    <span slot="header">Release notes</span>
    <a-text>Line one. Line two. Line three. Line four. Line five. Line six. Line seven. Line eight. Line nine. Line ten. Line eleven. Line twelve.</a-text>
    <style is:inline>{`
      a-card.scrollable::part(body) { overflow: auto; }
    `}</style>
  </a-card>
</Preview>

```css folded
/* cap the card's height, then let the body scroll */
a-card.scrollable { height: 160px; }
a-card.scrollable::part(body) { overflow: auto; }
```

**Separate the header** with a divider by styling `::part(header)`:

<Preview background="var(--bg-2)">
  <a-card class="divided" style={{ width: '320px' }}>
    <span slot="header">With a divider</span>
    <a-text>A hairline under the header, drawn on the part.</a-text>
    <style is:inline>{`
      a-card.divided::part(header) {
        padding-bottom: 8px;
        border-bottom: 1px solid var(--border-5);
      }
    `}</style>
  </a-card>
</Preview>

```css folded
a-card.divided::part(header) {
  padding-bottom: 8px;
  border-bottom: 1px solid var(--border-5);
}
```

</Disclosure>
