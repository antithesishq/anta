# Select

A single- or multi-select dropdown: a read-only field showing the chosen
value(s), and a menu of options to pick from. Click the field to open the menu; it
anchors to the field, dismisses on outside-click or `Esc`, and highlights the
chosen row.

Select is a **composed component** — not a new element, but an
[Input](/components/input/) trigger stitched to a [Menu](/components/menu/), with
the wrapper coordinating value and open state. Options come from a JSON array of
bare strings or objects (like [RadioGroup](/components/radio/) /
[Tabs](/components/tabs/)); changes arrive through one **`onValueChange`**
callback. Control it with `value` or leave it uncontrolled with `defaultValue`.

Requires `@antadesign/anta/elements` (client-side only).

```tsx folded
<Select
  label="Field"
  options={[
    { value: 'output_text', hint: 'Raw log message or event payload', icon: 'file' },
    { value: 'stream', hint: 'Log level: error · info · internal', icon: 'braces' },
    { value: 'container', hint: 'Host where the event occurred', icon: 'cube' },
    { value: 'archived', hint: 'Read-only snapshot', icon: 'folder-close', disabled: true },
    { value: 'flagged', hint: 'Needs review', icon: 'warning-triangle', tone: 'warning' },
    { value: 'custom', hint: 'Your own field path', icon: 'asterisk', tone: '#c026d3' },
  ]}
/>
```

</Col>
<Col>

`options` takes bare strings or objects. A string is shorthand for
`{ value, label: value }`. An object adds a `label`, a `hint` (the secondary line),
a leading `icon`, a per-option `tone` (a named tone or a custom CSS color), or
`disabled`. Open the field: the chosen row is highlighted, and the disabled row is
skipped by the keyboard.

</Col>
</Columns>

## Selection modes

<Columns>
<Col>

<Preview>
  <SelectModesDemo client:load />
</Preview>

```tsx folded
// Single-select marks (value is a string)
<Select indicator="check" options={OPTIONS} value={one} onValueChange={setOne} />  // trailing ✓ + tint
<Select indicator="radio" options={OPTIONS} value={one} onValueChange={setOne} />  // leading radio
<Select options={OPTIONS} value={one} onValueChange={setOne} />                    // tint only (default)

// Tone the selected row — named tone or custom colour (indicator adopts it too)
<Select indicator="check" toneSelected="brand" options={OPTIONS} value={one} onValueChange={setOne} />
<Select indicator="radio" toneSelected="#c026d3" options={OPTIONS} value={one} onValueChange={setOne} />

// Multiple: checkboxes, count summary, Select-all row; value is a string[]
<Select
  selection="multiple"
  selectAll
  options={OPTIONS}
  value={many}
  onValueChange={setMany}
/>
```

</Col>
<Col>

`selection` sets **behaviour**, `indicator` sets the single-select **mark**.

`selection="single"` (the default) keeps `value` a string and closes on pick.
`indicator` then chooses the row mark: **`"none"`** (default — a tint-only
highlight), **`"check"`** (a trailing checkmark on the chosen row, keeping the tint
— the canonical Select look), or **`"radio"`** (a leading radio on every row).

`selection="multiple"` makes `value` a **string array**, puts a **checkbox** on
every row, keeps the menu open as you toggle, and summarises the count in the field
("N selected"). Add **`selectAll`** for a top row that toggles everything — its box
goes mixed when only some are on.

Each checkable row is the control itself (`role="menuitemcheckbox"` /
`menuitemradio`, `aria-checked`); the checkbox / radio / check is a passive
indicator, not a nested control.

**`toneSelected`** tones the selected row(s): the whole row takes the tone — label,
icon, indicator, and tint. Pass a named tone or any CSS color (a custom color keeps
its hue, with lightness pinned to the brand text). It reads strongest with
`indicator` `none` / `check`, which show the row tint; `radio` / `checkbox` have no
row tint, so it tones the label and indicator only.

</Col>
</Columns>

## Value & changes

<Columns>
<Col>

<Preview>
  <SelectControlledDemo client:load />
</Preview>

```tsx folded
const [field, setField] = useState('stream')

<Select
  label="Field"
  options={['output_text', 'stream', 'container', 'vtime', 'custom']}
  value={field}
  onValueChange={(v) => setField(v)}
/>
```

</Col>
<Col>

Leave `value` off and pass `defaultValue` for an **uncontrolled** select (the
wrapper owns the value). Pass `value` to **control** it — the field follows the
prop, and a pick only requests a change that you apply in `onValueChange`.

**`onValueChange(value, attrs)`** is the single selection callback — the new value
first (a string, or a string array in `multiple` mode), with a snapshot second:
`{ value, option }` for the changed row, plus `selected` in `multiple` mode (or
`{ all: true }` for the Select-all row). There's deliberately **no
`onStateChange`**: Select has no discrete element state to veto (unlike Checkbox or
RadioGroup), so it follows Input's model — one value callback, and a controlled
consumer rejects by not updating `value`. See the
[event-model note on Input](/components/input/#events) for the full rationale.

</Col>
</Columns>

```tsx folded
<Select label="Small · info"    size="small"  status="info"     hint="Lowercase & dashes only" options={OPTIONS} defaultValue="stream" />
<Select label="Medium · success" size="medium" status="success"  hint="Field is valid" options={OPTIONS} defaultValue="stream" />
<Select label="Large · critical" size="large"  status="critical" hint="Pick a field" options={OPTIONS} placeholder="Required…" />
{/* statusIcon overrides the per-status glyph (or `false` drops it) — like Input */}
<Select status="info" statusIcon="sparkles" hint="Custom glyph" options={OPTIONS} defaultValue="stream" />
```

</Col>
<Col>

The trigger is an [Input](/components/input/), so it inherits the field props.
**`size`** (`small` · `medium` · `large`) sets the height and type scale.
**`status`** paints a validation tone on the border and `hint` and prefixes a glyph
(`info` / `success` / `warning` / `critical`); **`statusIcon`** overrides that glyph
(any shape, or `false` to drop it), exactly as on Input. The message rides in `hint`.

`status` is a validation *state*, not `tone` — same palette, but it also carries the
glyph and (for `critical`) validity. See the [Input status note](/components/input/#status).
The field also takes `label`, `placeholder`, `round`, and `disabled`, and fills its
container — set a width via `style` / `className` (both forwarded to the field).

</Col>
</Columns>

## Components composition

`Select` has no `<a-select>` element — the JSX wrapper *is* the coordinator. It
renders an `<Input readOnly>` followed by a `<Menu>`, holds the value and open
state, reflects the value into the field and into each option's `selected`, and
turns a `MenuItem` pick into `onValueChange`. Everything hard — positioning,
outside-click / Esc dismiss, in-menu arrow / type-ahead keyboard — comes from
`Menu` for free.

<Preview>
  <SelectBasicDemo client:load />
</Preview>

Because it's a composition, the same result is reachable **without React** by
hand-assembling the pieces — the menu anchors to its previous sibling, so a field
plus a menu plus a little glue is a working select:

```html folded
<!-- `.select` is your own wrapper class — everything below is scoped to it. -->
<div class="select" style="width: 240px">
  <!-- Read-only field trigger; `dim-actions` dims the chevron at rest. The 7px
       inline margin + transition on the chevron match <Select>. -->
  <a-input readonly dim-actions value="stream" aria-haspopup="menu">
    <a-icon slot="trailing" shape="chevron-down" style="margin-inline-end: 7px; transition: transform 150ms ease"></a-icon>
  </a-input>
  <a-menu>
    <a-menu-item value="output_text"><a-menu-item-label>output_text</a-menu-item-label></a-menu-item>
    <a-menu-item value="stream" selected><a-menu-item-label>stream</a-menu-item-label></a-menu-item>
    <a-menu-item value="container"><a-menu-item-label>container</a-menu-item-label></a-menu-item>
  </a-menu>
</div>
<script type="module">
  import '@antadesign/anta/elements'
  const root = document.querySelector('.select')
  const field = root.querySelector('a-input')
  const menu = root.querySelector('a-menu')
  const chevron = field.querySelector('a-icon')
  // Flip the chevron with the menu's open state (as <Select> does).
  menu.addEventListener('statechange', (e) => {
    chevron.style.transform = e.detail.next === 'open' ? 'rotate(180deg)' : ''
  })
  // On pick: mark the row selected + reflect its label into the field.
  menu.addEventListener('click', (e) => {
    const item = e.target.closest('a-menu-item')
    if (!item) return
    menu.querySelectorAll('a-menu-item').forEach((el) => el.toggleAttribute('selected', el === item))
    field.value = item.querySelector('a-menu-item-label').textContent
  })
</script>
```

`Menu` gives you open/close, positioning, and dismissal; you supply the small bit
of glue that tracks which item is `selected`, flips the chevron, and updates the
field. The React `Select` packages exactly this.

<Disclosure title="Styling">

Select is an [Input](/components/input/) plus a [Menu](/components/menu/), so it
inherits both surfaces' hooks. Reach for props first, plain CSS or `::part` for the
rest — never override an element's internal `--*` output tokens.

**Selection colour** goes through the props, not CSS: a per-option `tone`, or
`toneSelected` for the chosen row(s). Both take a named tone or any CSS color (a
custom color keeps its hue, with lightness pinned to the brand text).

**The field** is styled through Input's props (`size`, `status`, `round`) and its
`::part`s; set its width with `style` / `className` (forwarded to the field). **The
popover** takes Menu's `::part(menu)`.

```tsx folded
// Tone the selection; give the trigger a width.
<Select toneSelected="brand" style={{ width: '220px' }} options={OPTIONS} />
```

**Borderless trigger.** The field's border is an inset `box-shadow`, so you can drop
it *at rest* and let the standard hover / focus shadow return on its own — no need to
re-declare it. Pair that with hiding the chevron for a field that reads as plain text
until you reach for it. Hide the chevron by targeting the trailing `a-icon` (its slot
wrapper is inline-`display:contents`, so hit the icon itself).
