# @antadesign/stickers package guidance

A companion package to `@antadesign/anta`, published separately on npm so that
core anta carries **no `lottie-web`** and no sticker code. Apps that don't use
stickers never install the animation runtime; apps that do use the compatible
`@antadesign/anta` already installed by the consumer and add
`@antadesign/stickers`, which pulls `lottie-web` transitively.

This package follows the shared root [`../AGENTS.md`](../AGENTS.md) conventions.
Before changing sticker elements or JSX wrappers, also read
[`../src/AGENTS.md`](../src/AGENTS.md): the two-tier architecture, declarative
DOM, boolean-attribute presence matching, color treatment, and docs-in-sync
rules apply here too. Only package-specific notes live here.

## Layout

- `src/elements/a-sticker.{ts,css}` — static SVG carrier `<a-sticker>`.
- `src/elements/a-sticker-animated.{ts,css}` — Lottie carrier `<a-sticker-animated>`. **The only `lottie-web` importer.**
- `src/elements/index.ts` — barrel registering both elements.
- `src/Sticker.tsx`, `src/StickerAnimated.tsx` — JSX wrappers. They emit `<a-sticker>` / `<a-sticker-animated>` and import shared helpers from `@antadesign/anta` (`@antadesign/anta/anta_helpers`, `@antadesign/anta/general_types`).
- `src/jsx.d.ts` — augments `@antadesign/anta/jsx-runtime`'s `JSX.IntrinsicElements` with the two sticker tags (anta itself ships no sticker types).
- `src/assets/<name>/<name>.{json,svg}` — source artwork (Lottie JSON + static SVG pose). One subfolder per sticker.
- `src/generated/` — **generated, committed** per-sticker modules + barrel. Do not hand-edit; run `pnpm run stickers` after changing `src/assets/`.
- `scripts/generate-stickers.mjs` — the generator (also published for consumers to build their own packs; `--package` sets the emitted import specifier).

## Coupling to anta

The JSX runtime is anta's (`jsxImportSource: "@antadesign/anta"`).
`@antadesign/anta` is a **peer dependency** (`>=0.3.31`) so stickers uses the
compatible Anta version already installed by the consumer; the matching
`workspace:*` dev dependency links the local package for builds. `lottie-web`
is this package's own dependency; `react` is also a peer.

## Build & dev

Same shape as anta: `pnpm run build` = `build:js` (esbuild) + `build:css` (copy CSS + the generator) + `build:types` (tsc). `dist/` is gitignored and regenerated by `prepare` / `prepublishOnly`. The repo-root `pnpm run dev` builds this package after anta and before the site.

```sh
pnpm run stickers   # regenerate src/generated/ from src/assets/
pnpm run build      # full build
pnpm run typecheck
```

## Publishing

See [`../RELEASING.md`](../RELEASING.md) for the mandatory package order and commands. The two package-specific things to remember here:

- **Publish `@antadesign/anta` first.** Stickers requires a consumer-provided
  Anta version satisfying its peer range, and that Anta release must already be
  on npm with the exports stickers imports (`./anta_helpers`, `./general_types`).
- **Use `pnpm publish`, not `npm publish`** — only pnpm rewrites the
  `workspace:*` protocol. Access + tag come from `publishConfig`
  (`{ access: "public", tag: "latest" }`), so no flags are needed:

```sh
npm version patch   # bump first (immutable versions)
pnpm publish --no-git-checks
```
